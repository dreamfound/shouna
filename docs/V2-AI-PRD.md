## 文档职责

本页回答：**V2（AI 接入版）要做什么、每条怎么验收、什么数据会离开设备**。

它不回答「代码怎么写」（那是 `docs/code-map/02-数据与领域.md`），也不回答「V1 做什么」（那是 `docs/PRD.md`）。本页只写**需求与验收口径**，不定义类名、表结构、接口签名。

## 阅读入口

- **何时读**：V2 立项、写 V2 验收用例、改 AI 相关页面与设置时。
- **前置约束**：`AGENTS.md`（协作规则）；`docs/实现约束.md`（动代码前必读）。
- **不适用**：只做 V1 的开发与验收。V1 期间本页全部条目**不实现、不占页面、不出现任何文案**。
- **口径优先级**：代码 > `docs/code-map/` > `docs/实现约束.md` > 架构文档与 PRD 行文。

**一句话结论**：在 V1 的离线台账之上加一条**可选的 AI 旁路**——用户**说一句、或者拍一张**，AI 把它变成一份**草稿**，用户确认后才落库；配置面对用户只留「**开关 + 密钥 + 用量**」（2026-10-08 裁定**不做能力槽**，厂家与模型维持硬编码），提示词与温度属开发侧常量；**物品数据永不出设备**，出设备的只有用户自己输入的那句话、位置**名称**清单、他主动挑的那张照片、以及已有的分类名称。

## 1. 背景与目标

**现状（事实）**

| 事实 | 依据 |
|---|---|
| 记录主流程是「连续录入页逐件打字」 | `docs/PRD.md` §6（P-ADD） |
| 既有语音按钮只把识别文本**追加写进单个字段**，不产生结构化结果 | `app/src/main/java/com/dream/shouna/ui/component/ai/VoiceInputDialog.kt` |
| 既有拍照只挂到**单条**记录上，不识别内容 | `app/src/main/java/com/dream/shouna/util/PhotoStore.kt`、`ui/component/item/PhotoInputRow.kt` |
| 工程内**零 AI 实现**：无网络层、无 `INTERNET` 权限（**本行是 V2 立项时的基线**；截至 2026-10-08，`data/remote/ai/` 与 `INTERNET` 权限**均已落地**，见 §4） | `app/src/main/java/` 下无 `data/remote/`；`app/src/main/AndroidManifest.xml` |

**目标**：把「说话」与「拍照」升级为**一次录入一批**的入口，降低录入成本；查询侧只做「把语音变成搜索词」，不引入 AI。

**成功标准（暂定目标，待首次实测后校准）**

1. 含 1 处位置 + 2 件物品的一句话，从松手到出现结果（逐条确认弹窗）≤ 8 秒（P50，网络正常）。
2. 不回归 V1：连续录入 5 件 ≤ 40 秒（`PRD.md §9` NFR-08）；**AI 未开启时行为与 v1.5 完全一致**。

## 3. 名词与口径

| 名词 | 口径 |
|---|---|
| **通道** | 用户提交内容的方式：文字 / 语音 / 照片 |
| **意图** | 内容要完成的事：**录入**（往库里写）/ **查询**（从库里读） |
| **草稿** | AI 的结构化产出。**永不直接落库**，必须经用户确认 |
| **确认卡** | **页内一段**（非弹层），逐行展示草稿字段并标注「已匹配 / 待新建」。**2026-10-09 起只剩录入页（P-ADD）用此形态**（首页两个 AI 入口改为独立页面、结果走逐条确认弹窗） |
| **逐条确认弹窗** | **语音 AI 录入页（P-VOICE-AI）与**拍照 AI 录入页（P-PHOTO-AI）的结果形态（**2026-10-09 起**）：**一件一弹**（`AlertDialog`），可改**名称 / 分类 / 备注**（**位置：语音可改 / 拍照只读**），三个出口 = **确认**（立刻落库这一件）/ **放弃**（跳过这一件）/ **关闭**（放弃本次录入）。与「确认卡」是**同一份草稿数据的两种呈现**，共用 `AiIntake` 的解析与落库（弹窗 `ui/component/ai/AiItemDialog`、队列 `ui/component/ai/AiItemQueue`） |
| **位置清单** | 位置树的**层序文本**：按树序（父在前、子在后）逐行列出节点名，**用缩进表示层级**（越深越右）。只含层名，不含物品、不含内部 id；清单缺中间层时**向上补全**，保证父链完整 |

> 通道 × 意图的组合与「哪一格真的需要 AI」，见 `docs/code-map/02-数据与领域.md`；本页只定需求。

## 4. 功能需求

编号沿用 `PRD.md §14` 的 `V2-FR-*` 空间**从 09 续编**；`V2-FR-01`～`V2-FR-08` 以 `PRD.md §14.3` 为真源，本页不重写。

| 编号 | 需求 | 输入 → 输出 | 验收要点 |
|---|---|---|---|
| **V2-FR-09** | **多物品拆解** | 一句话 / 一张图 → N 行草稿 | 含 2 件物品 → 出 2 行；只含 1 件 → 出 1 行；识别不出物品 → **不出卡**，只给一行提示；每行可改可弃 |
| **V2-FR-10** | **语音句录入** | 长按说话 → 逐条确认弹窗 | ✅ **2026-10-08 已落地；2026-10-09 落点由「首页页内确认卡」改为独立页面 P-VOICE-AI**（路由 `VoiceAiIntake`，页面 `ui/screen/ai/`），入口 = 首页「🎤 语音AI记」（仅 AI 总开关开启时出现、**只做导航**）。松手即识别，**用户不接触原始文本**；结果走**逐条确认弹窗**（弹窗内**位置可改**），位置口径 = **不新建、降级到最近已存在祖先**（见下方 2026-10-09 补注）。⚠️ 原文「AI 未开启时该按钮回落为 V1 行为」**只对录入页那条 🎤 成立** —— 首页没有字段可写，该入口改为**不出现** |
| **V2-FR-11** | **拍照识别录入** | 一张照片 + 已定位置 → 多件（**一件一弹**）→ 逐条落库 | ✅ **2026-10-08 已落地**，落点 = **首页「📷 拍照AI记」→ 独立页面 P-PHOTO-AI**（**2026-10-09 由页内展开面板改**，见本节下方补注）+ 录入页照片通道。**结果形态 = 逐条确认弹窗**（**2026-10-09 二次改**）：识别出的每件**各弹一次**，弹窗内可改**名称 / 分类 / 备注**（**位置只读** —— 识别前已定，`V2-FR-13`），三个出口 = **确认**（**立刻弹下一件**，这一件的写库交后台串行队列 —— **2026-10-09 三次改**）/ **放弃**（跳过这一件，**不算失败**）/ **关闭**（放弃本次录入；**已确认的留在库里**）；**未点确认前库中零新增**；一张图**不产生多份照片副本**（原图**留存**为这批记录的照片、`photo_path` 只存文件名，N 条记录**共用同一个文件** ⇒ 删文件前须**判引用**，见下方补注） |
| **V2-FR-12** | **位置清单入参** | 位置清单 → 模型 | 调模型时**必附**位置清单；清单只含**路径文本**（不含物品、不含内部 id）；模型返回路径文本，本地归一化匹配回节点 |
| **V2-FR-13** | **位置先定后用** | 用户先定位置 → 再拍照 | 拍照入录入口在**无目标位置时不可用**并给提示；模型的返回中**不含位置字段** |
| **V2-FR-14** | **语音查询** | 说话 → 搜索框 | 识别文本直接填入搜索框，走本地检索；**AI 调用计数为 0**；AI 未开启也可用 |
| **V2-FR-15**（**2026-10-08 裁定不实施**） | **用户可见配置面** | — | 实际口径 = **总开关（默认关）+ 密钥 + 本周期用量** —— 厂家与两个模型槽**不做**（维持硬编码，`deepseek-flash`）。关闭开关后**立刻停止一切请求且不删密钥**；界面**不出现**温度、提示词、端点等项 |
| **V2-FR-16** | **开发侧配置面** | — | 提示词**按功能各一套**（录入 / 图片 / 查询）、温度、端点、JSON 输出契约 = **代码内常量**；界面与文案中不出现这些项；改提示词**不需改本页** |

**`V2-FR-10` 的落点补注（2026-10-08 追补实现）**

| 项 | 口径 |
|---|---|
| 一句话可含 | **不同位置的不同东西**、**同一位置的多个东西** —— 两者由「多行草稿」这一个机制同时覆盖（每行各带 `location_path`） |
| 「用户不接触原始文本」 | 成立：识别结果**不落到任何输入框**，用户只在结果段（原为页内确认卡，2026-10-09 起为逐条确认弹窗）上看到解析出的行 |
| AI 未开启时 | 该入口**不出现**（不是「回落为写字段」）。理由：① 首页没有「当前字段」可写；② 拆句与拆位置必须过 AI，关着时它连拆都拆不了，造一个点了没用的入口比不出现更糟；③ 与「开关关着时不新增任何界面、零网络请求」这条硬约束一致 |
| 录入页的 🎤 | **保持 V1 FR-18 形态不变**（识别文本追加写进名称 / 备注框），与首页入口**并存**：一个是「说一整句、拆成多件」，一个是「往一个框里补一句」 |

**`V2-FR-10` 落点补注（2026-10-09 追补：独立成页 + 位置降级不新建）**

| 项 | 口径 |
|---|---|
| 落点 | **独立页面 P-VOICE-AI**（路由 `VoiceAiIntake`，页面 `ui/screen/ai/`）。入口 = 首页「🎤 语音AI记」，**仅 AI 总开关开启时出现、只做导航**。页内 = **一个话筒 + 状态行 + 落库汇总**，没有位置条、没有「识别」按钮（松手即识别）。 |
| 结果形态 | **逐条确认弹窗**（`ui/component/ai/AiItemDialog`，与拍照页共用；队列与后台串行落库在 `ui/component/ai/AiItemQueue`）：一件一弹，可改**名称 / 分类 / 备注**，**位置可改**（位置是模型猜的）；三出口 = **确认**（立刻弹下一件，写库后台跑）/ **放弃**（跳过）/ **关闭**（放弃本次录入）。 |
| 位置口径（本次定） | **不新建位置**：`LocationPathMatcher` 逐层下沉，命中的最深层即落点；树里不存在的更深的层**直接丢弃**并**降级到最近的已存在祖先**（例：「客厅 › 抽屉」而「抽屉」不存在 ⇒ 记到「客厅」）。被丢弃的层名进 `AiDraftRow.droppedLocationNames`，弹窗据此标**「已就近」**。由 `AiIntake.parseText(createMissingLayers = false)` 兑现（录入页仍为 `true` ⇒ 标「待新建」）。 |
| 一个祖先都没对上 | 该行**没有位置**，但仍**进弹窗**；`AiItemEdit.canConfirm` 为假 ⇒「确认」**置灰**，用户**就地补一个位置**即解禁（与识别结果的初值无关）。**不再有「无位置行被静默跳过」的口径**。 |
| 与拍照页的分野 | 位置来源相反：语音 = **模型从那句话里猜**（可错、可降级、可没有 ⇒ 弹窗内可改）；拍照 = **用户识别前亲手选**（`V2-FR-13`，模型不参与 ⇒ 弹窗内只读）。 |
| 提示词（2026-10-09 再补） | **本页有自己的一套功能提示词**（功能场景 `VOICE_INPUT`），**不再与录入页的文字通道共用** —— 用户 2026-10-09 口径。理由：文字通道有表单兜底（用户已选位置），语音通道**没有**，两者的注意点不同；语音这一段还明说「这是一段语音转文字」。位置清单与「逐字照抄」指令仍在共用的上下文段里。两个语音口径（独立场景 + 位置不新建）在 `AiIntake.parseSpokenText` 一处收口。 |
| 识别内核（2026-10-10 追加） | **与落点、结果形态都无关**：本页只把「说话」变成文字，用哪条通道由**双通道路由**决定（系统优先 → 不可用则内置离线引擎）。对用户的可见差别只有一处：**机型没有系统识别服务时，本页照样能用**（在此之前是「没有可用的语音识别服务」一句死话）。同一个内核也服务录入页那条 🎤（FR-18），两处行为一致。 |

**`V2-FR-11` 的落点补注（2026-10-08 追补实现）**

| 项 | 口径 |
|---|---|
| 落点 | **首页（P-HOME）「📷 拍照AI记」→ 独立页面 P-PHOTO-AI**（路由 `PhotoAiIntake`，页面 `ui/screen/ai/`；**2026-10-09 由「首页页内展开面板」改为独立页面** —— 原顾虑「面板里要开位置选择、而 `LocationPickerSheet` 本身是弹层，弹窗套弹层会叠两个窗口」在独立页面下自然消解，AI 失败提示也有了固定落点）：页内 **先**选位置（必填）→ **再**拍 / 选一张照片 → **最后**点「识别」→ **逐条确认弹窗**（一件一弹）→ **留在本页**（位置保留，可接着拍下一张）。首页按钮**仅 AI 总开关开启时出现**；录入页的 AI 按钮照片通道**并存** |
| 顺序 | **位置 → 照片 → 识别**（硬口径，`V2-FR-13`）：模型这一路**永不返回位置**，故没有位置就没有落点 ⇒ 未选位置时「识别」不可点（给红字原因，不弹窗） |
| 结果形态（2026-10-09 二次改） | **逐条确认弹窗**（`AlertDialog`，一次只呈现一件；标题给「确认第 i / N 件」）：可改**名称 / 分类 / 备注**，**位置只读**（识别前已定；想换位置只能「关闭」整轮、回页面重选再识别）。三出口 —— **确认** = **立刻弹下一件**，这一件的写库**投给后台串行队列**（应用级作用域 + 锁内 FIFO；**2026-10-09 三次改** 前是「先落库、后前进」—— 弹窗不为写库停一帧，且**重复点确认不可能发生**，因为上一件在点击那一帧就离开了弹窗）；**放弃** = 跳过这一件（不落库、**不计入「没记下」**，那是给写库失败的信号）；**关闭**（右上角按钮 / 点弹窗外 / 系统返回键）= **放弃本次录入**，**已确认的留在库里**、剩下的未处理件丢弃。**为什么件件落库而不攒批**：「确认」的字面承诺就是「这笔记下了」；攒批会让「关闭」两难。⚠️ 逐条调用 `commitRows` 使它的「同批待新建层复用节点」缓存**按件重建** —— 照片通道的位置在 `parsePhoto` 里已覆写成**已存在**的位置（`pendingLocationNames` 恒空），**当前无影响**；**将来若放开弹窗内改位置，必须改回批量调用** |
| 原图是否留存 | **留存**（用户 2026-10-08 裁定，**推翻 §8 第 3 项原推荐的「不留存」**）：识别用的原图作为这批记录的照片。`photo_path` 存**文件名** ⇒ N 条记录**共用同一个文件**（**非物理复制 N 份**） |
| 共用文件的删除口径（2026-10-09 补） | 因为共用同一个文件，**删除照片必须先判引用**：详情页「移除照片」与编辑页换 / 删图时，只有「本条是这张照片的**最后一个引用者**」才真删文件，否则只清本条记录的照片字段。**不这样做的后果**：删 A 的照片会让 B 变成破图（`photo_path` 还指着已被删掉的文件）。横切规则见 `docs/实现约束.md` §2-12。**2026-10-09 三次补第三道闸**：拍照页写库改为后台串行后，**在途落库未结算时一律不删**（那些任务引用的图 `photo_path` 还没进库 ⇒ 引用计数恒为 0，只看计数会误删）；判据入口 `PhotoAiIntakeViewModel.canDeletePhotoFile`，页面 `onBack` 与照片行的替换 / 移除都过它 |
| 一张图配多行 | 落库时把该文件名**逐条**透传；**第一件落库成功即清页面态文件名**（那张图已归库，页面不能再持有 —— 否则「照片行的替换即删 / 离开本页即删」会删掉库里正在用的图）；**离开本页**（页内「返回」按钮或系统返回键）才删**尚未落库**的临时图，且**先判引用**（`canDeletePhotoFile`：无在途落库 **且** 库中零引用）；旋转 / 进程内重组**不触发**清理（与 `PhotoInputRow`「不在 `onDispose` 里删」同一取舍）。**已知残余**：用户在「刚确认、写库尚未结算完」时离开页面 ⇒ 页面不删（这是对的），若这批最终一件都没写成功，那张图会留在私有目录无人引用（取舍见 `实现约束.md` §2-12） |

**沿用 `PRD.md §14` 的三条硬约束**：`V2-FR-04`（AI 产出永不直接落库）、`V2-FR-07`（失败一律回落人工，不阻塞）、`V2-FR-08`（用量可见、可一键关闭）。

## 7. 信息查找（**需求待澄清，本版不给验收标准**）

**事实**：本地检索已支持名称 / 拼音 / 位置 / 分类四档匹配 + 三维筛选，1000 件 ≤ 300ms（`PRD.md §9` NFR-05）。

| 「统计位置下的信息」 | 需求未明确 | 同上 |

**必须先回答的三个问句**

1. 上一次你想找东西**没找到**，是什么时候、找的是什么？（看频次）
2. 当时你怎么找的，结果哪里让你不满意？（看当前方案有多烂）
3. 「统计位置下的信息」——给我一句你**真会问出口**的话。

三个问句有答案前，本条不进入验收范围。
