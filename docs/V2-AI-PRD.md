## 文档职责

本页回答：**V2（AI 接入版）要做什么、每条怎么验收、什么数据会离开设备**。

它不回答「代码怎么写」（那是 `docs/code-map/02-数据与领域.md`），也不回答「V1 做什么」（那是 `docs/PRD.md`）。本页只写**需求与验收口径**，不定义类名、表结构、接口签名。

## 阅读入口

- **何时读**：V2 立项、写 V2 验收用例、改 AI 相关页面与设置时。
- **前置约束**：`AGENTS.md`（协作规则）；`docs/实现约束.md`（动代码前必读）。
- **不适用**：只做 V1 的开发与验收。V1 期间本页全部条目**不实现、不占页面、不出现任何文案**。
- **口径优先级**：代码 > `docs/code-map/` > `docs/实现约束.md` > 架构文档与 PRD 行文。

**一句话结论**：在 V1 的离线台账之上加一条**可选的 AI 旁路**——用户**说一句、或者拍一张**，AI 把它变成一份**草稿**，用户确认后才落库；配置面对用户只留「**开关 + 密钥 + 用量**」（2026-10-08 裁定**不做能力槽**，厂家与模型维持硬编码），提示词与温度属开发侧常量；**物品数据永不出设备**，出设备的只有用户自己输入的那句话、位置**名称**清单、他主动挑的那张照片、以及已有的分类名称。

## 1. 背景与目标

**现状（事实）**

| 事实 | 依据 |
|---|---|
| 记录主流程是「连续录入页逐件打字」 | `docs/PRD.md` §6（P-ADD） |
| 既有语音按钮只把识别文本**追加写进单个字段**，不产生结构化结果 | `app/src/main/java/com/dream/shouna/ui/component/VoiceInputDialog.kt` |
| 既有拍照只挂到**单条**记录上，不识别内容 | `app/src/main/java/com/dream/shouna/util/PhotoStore.kt`、`ui/component/PhotoInputRow.kt` |
| 工程内**零 AI 实现**：无网络层、无 `INTERNET` 权限（**本行是 V2 立项时的基线**；截至 2026-10-08，`data/remote/ai/` 与 `INTERNET` 权限**均已落地**，见 §4） | `app/src/main/java/` 下无 `data/remote/`；`app/src/main/AndroidManifest.xml` |

**目标**：把「说话」与「拍照」升级为**一次录入一批**的入口，降低录入成本；查询侧只做「把语音变成搜索词」，不引入 AI。

**成功标准（暂定目标，待首次实测后校准）**

1. 含 1 处位置 + 2 件物品的一句话，从松手到出现确认卡 ≤ 8 秒（P50，网络正常）。
2. 拍一张书桌照片，识别出 ≥ 3 件物品且无幻觉项（人工判定），从拍照到出确认卡 ≤ 12 秒。
3. 不回归 V1：连续录入 5 件 ≤ 40 秒（`PRD.md §9` NFR-08）；**AI 未开启时行为与 v1.5 完全一致**。

## 3. 名词与口径

| 名词 | 口径 |
|---|---|
| **通道** | 用户提交内容的方式：文字 / 语音 / 照片 |
| **意图** | 内容要完成的事：**录入**（往库里写）/ **查询**（从库里读） |
| ~~**能力槽**~~ | ~~用户可配的模型位，**只有两个**：**文本槽**（服务文字与语音通道）/ **视觉槽**（服务照片通道）~~ —— **2026-10-08 用户裁定不做能力槽、模型维持硬编码单模型，本名词作废** |
| **草稿** | AI 的结构化产出。**永不直接落库**，必须经用户确认 |
| **确认卡** | **页内一段**（非弹层），逐行展示草稿字段并标注「已匹配 / 待新建」 |
| **位置清单** | 位置树的**层序文本**：按树序（父在前、子在后）逐行列出节点名，**用缩进表示层级**（越深越右）。只含层名，不含物品、不含内部 id；清单缺中间层时**向上补全**，保证父链完整 |

> 通道 × 意图的组合与「哪一格真的需要 AI」，见 `docs/code-map/02-数据与领域.md`；本页只定需求。

## 4. 功能需求

编号沿用 `PRD.md §14` 的 `V2-FR-*` 空间**从 09 续编**；`V2-FR-01`～`V2-FR-08` 以 `PRD.md §14.3` 为真源，本页不重写。

| 编号 | 需求 | 输入 → 输出 | 验收要点 |
|---|---|---|---|
| **V2-FR-09** | **多物品拆解** | 一句话 / 一张图 → N 行草稿 | 含 2 件物品 → 出 2 行；只含 1 件 → 出 1 行；识别不出物品 → **不出卡**，只给一行提示；每行可改可弃 |
| **V2-FR-10** | **语音句录入** | 长按说话 → 确认卡 | ✅ **2026-10-08 已落地**，落点 = **首页「🎤 说一句」**（口径见本节下方补注）。松手后自动转文本并进 AI，**用户不接触原始文本**；⚠️ 原文「AI 未开启时该按钮回落为 V1 行为（文本写进当前字段）」**只对录入页那条 🎤 成立** —— 首页没有字段可写，该入口改为**不出现** |
| **V2-FR-11** | **拍照识别录入** | 一张照片 + 已定位置 → 多行草稿 → 批量落库 | ✅ **2026-10-08 已落地**，落点 = **首页「📷 拍照AI记」**（**页内展开面板**，见本节下方补注）+ 录入页照片通道。默认全选，**可逐行取消**；⚠️ 原文「可逐行**改分类**」**未实现**（2026-10-08 登记，理由见 `docs/code-map/02-数据与领域.md`）；**未点确认前库中零新增**；一张图**不产生多份照片副本**（原图**留存**为这批记录的照片、`photo_path` 只存文件名，N 条记录**共用同一个文件**） |
| **V2-FR-12** | **位置清单入参** | 位置清单 → 模型 | 调模型时**必附**位置清单；清单只含**路径文本**（不含物品、不含内部 id）；模型返回路径文本，本地归一化匹配回节点 |
| **V2-FR-13** | **位置先定后用** | 用户先定位置 → 再拍照 | 拍照入录入口在**无目标位置时不可用**并给提示；模型的返回中**不含位置字段** |
| **V2-FR-14** | **语音查询** | 说话 → 搜索框 | 识别文本直接填入搜索框，走本地检索；**AI 调用计数为 0**；AI 未开启也可用 |
| ~~**V2-FR-15**~~ **（2026-10-08 裁定不实施）** | ~~**用户可见配置面**~~ | — | ~~设置页 AI 节 **仅**：总开关（默认关）、厂家、文本模型、视觉模型、密钥、本周期用量~~。**实际口径 = 总开关（默认关）+ 密钥 + 本周期用量**——厂家与两个模型槽**不做**（维持硬编码，`deepseek-flash`）。关闭开关后**立刻停止一切请求且不删密钥**；界面**不出现**温度、提示词、端点等项 |
| **V2-FR-16** | **开发侧配置面** | — | 提示词**按功能各一套**（录入 / 图片 / 查询）、温度、端点、JSON 输出契约 = **代码内常量**；界面与文案中不出现这些项；改提示词**不需改本页** |

**`V2-FR-10` 的落点补注（2026-10-08 追补实现）**

| 项 | 口径 |
|---|---|
| 落点 | **首页（P-HOME）**：一键「🎤 说一句」→ 系统转文字 → **直接进 AI** → **首页页内确认卡** → 一次确认、一次落库。不跳录入页、不新增路由 |
| 一句话可含 | **不同位置的不同东西**、**同一位置的多个东西** —— 两者由「多行草稿」这一个机制同时覆盖（每行各带 `location_path`） |
| 「用户不接触原始文本」 | 成立：识别结果**不落到任何输入框**，用户只在确认卡上看到解析出的行 |
| AI 未开启时 | 该入口**不出现**（不是「回落为写字段」）。理由：① 首页没有「当前字段」可写；② 拆句与拆位置必须过 AI，关着时它连拆都拆不了，造一个点了没用的入口比不出现更糟；③ 与「开关关着时不新增任何界面、零网络请求」这条硬约束一致 |
| 录入页的 🎤 | **保持 V1 FR-18 形态不变**（识别文本追加写进名称 / 备注框），与首页入口**并存**：一个是「说一整句、拆成多件」，一个是「往一个框里补一句」 |
| 位置从哪来 | 由**用户说的那句话**决定（模型返回 `location_path`，本地逐层匹配；未命中的层标「待新建」，**点确认后才建**）。首页**没有**「已选位置」兜底 ⇒ 完全没提位置的那件会被跳过，并在页面上**明说漏了几件** |

**`V2-FR-11` 的落点补注（2026-10-08 追补实现）**

| 项 | 口径 |
|---|---|
| 落点 | **首页（P-HOME）「📷 拍照AI记」**：点开**页内展开面板**（**不是弹窗** —— 面板里要开位置选择而它本身是 `ModalBottomSheet`，弹窗套弹层会叠两个窗口；页内展开只付重组成本）→ **先**选位置（必填）→ **再**拍 / 选一张照片 → **最后**点「识别」→ 出多行草稿 → 一次确认、一次落库。**仅 AI 总开关开启时出现**；录入页的 AI 按钮照片通道**并存** |
| 顺序 | **位置 → 照片 → 识别**（硬口径，`V2-FR-13`）：模型这一路**永不返回位置**，故没有位置就没有落点 ⇒ 未选位置时「识别」不可点（给红字原因，不弹窗） |
| 原图是否留存 | **留存**（用户 2026-10-08 裁定，**推翻 §8 第 3 项原推荐的「不留存」**）：识别用的原图作为这批记录的照片。`photo_path` 存**文件名** ⇒ N 条记录**共用同一个文件**（**非物理复制 N 份**）；代价是其中一条在编辑页换 / 删图会波及其他条 |
| 一张图配多行 | 落库时把该文件名透传给每条记录；**用户点「收起」**才删未落库的临时图，且**落库成功时先清面板态文件名再删**（否则会删掉库里正在用的图） |

**沿用 `PRD.md §14` 的三条硬约束**：`V2-FR-04`（AI 产出永不直接落库）、`V2-FR-07`（失败一律回落人工，不阻塞）、`V2-FR-08`（用量可见、可一键关闭）。

## 7. 信息查找（**需求待澄清，本版不给验收标准**）

**事实**：本地检索已支持名称 / 拼音 / 位置 / 分类四档匹配 + 三维筛选，1000 件 ≤ 300ms（`PRD.md §9` NFR-05）。

**结论：本版不引入 AI 查询。** 逐条拆解：

| 用户表述 | 判定 | 处置 |
|---|---|---|
| 「某个物品在哪里」 | **不需要 AI** | 见 `V2-FR-14`：语音 → 搜索框 → 本地检索 |
| 「模糊描述找物品」 | `V2-FR-05` 的**重开** | 先回答下面三个问句 |
| 「统计位置下的信息」 | 需求未明确 | 同上 |

**必须先回答的三个问句**

1. 上一次你想找东西**没找到**，是什么时候、找的是什么？（看频次）
2. 当时你怎么找的，结果哪里让你不满意？（看当前方案有多烂）
3. 「统计位置下的信息」——给我一句你**真会问出口**的话。

三个问句有答案前，本条不进入验收范围。
