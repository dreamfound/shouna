# 流程链路

## 文档职责

本文由 [`00-索引.md`](00-索引.md) 分出，逐条记录**10 条端到端链路**（A 冷启动 / B 记一件 / C 搜索 / D 详情与状态 / E 位置浏览 / F 位置选择弹层 / G 归纳统计 / H 物品编辑 / I 设置与分类管理 / J AI 录入旁路）的
「入口 → 逐跳文件·符号」，以及链路级的**状态归属边界**。
单文件职责见 [`01-界面层.md`](01-界面层.md) 与 [`02-数据与领域.md`](02-数据与领域.md)。

## 阅读入口

- **何时读**：任务跨文件（新增一条数据流、排查某一步为何不生效）时，先读对应链路。
- **读法**：先读链路图定位落脚文件，再按「关键边界」确认状态归属，最后按「代码定位」打开实现。
- **前置约束**：[`../实现约束.md`](../实现约束.md)（尤其 §2 状态与数据边界）；[`../../AGENTS.md`](../../AGENTS.md)。
- **不适用**：只改单个文件内部逻辑时，直接看 `01` / `02` 的对应行。
- **层级**：本文件只到「文件·符号」层级；**去抖时长、SQL、算法步骤一律以代码为准**，这里不抄。

## B｜记一件（FR-09 / 10 / 12 / **14** + 位置必填）

```
HomeScreen「＋ 记一件」→ goQuickAdd() ／ LocationBrowseScreen「＋ 往这里记一件」→ goQuickAdd(当前层 id)
  → QuickAddRoute(initialLocationId) → LaunchedEffect → QuickAddViewModel
  ① 初始位置（`initialize`，**整页只跑一次**，自带防重入守卫）：优先级 **路由指定 > 最近使用**
        LocationRepository.recentUsed()；指定位置**已不在树里**（参数失效）则回落最近使用
        →（两者皆无 = 首装无使用史，则不选，canSave 恒 false）
        ⚠ 必须在 VM 里守卫：配置变更会让 Route 的 `LaunchedEffect` 重跑，而 VM 挂在返回栈上存活不变，
          无守卫会把用户已改好的位置打回初始值
  ② 输入：onNameChange / onCategorySelected / onNoteChange → recomputeCanSave
        └─ canSave = 名称非空 ∧ 位置已选
        └─ onNameChange 同时清掉上一轮的相似提示（新名字不继承旧结论）
  ③ 选位置：位置条 → LocationPickerSheet（见流程 F）｜或 onCreateLocation 直接新建
  ④ 保存：onSaveAndContinue
        ├─ 先查重：ItemRepository.findSimilar(name)      ← FR-14 **必须先查后写**，
        │      否则会命中刚写进去的这条自己
        ├─ ItemRepository.createItemQuick
        │     ├─ PinyinUtil.keys → ItemEntity 的拼音列
        │     ├─ 三个时间列同一次 now（created / lastModified / **lastConfirmed**）← 录入即一次确认
        │     ├─ ItemDao.insert
        │     └─ LocationDao.touchLastUsed          ← FR-11 下次预选它
        └─ 命中则置 similarCount / similarItemId
  ⑤ 收尾：清名称 / 分类 / 备注（**保留位置**）→ sessionCount + 1 → Screen 依计数重新请求焦点
        写失败 → 静默返回，输入与计数不动（FR-10 零弹窗）
  ⑥ FR-14 提示（**非阻塞**，保存照常成功）：多渲染一行「已有 N 件同名或相近的物品」+「查看」
        └─ onViewSimilar → viewSimilarEvents → Route 收流 → goItemDetail(id)
```

## C｜搜索（FR-19 / 20 / **22** / 23 / 27）

```
HomeScreen 搜索框 → goSearch → SearchRoute（setInitialQuery）→ SearchViewModel
  ① 输入 → onQueryChange：只更新回显 + 写入内部输入通道
  ② 检索流（init 内）：输入通道去抖 × ItemRepository.observeSearchDocs()
        × ConfigRepository.thresholdMonths() × filters（FR-22）→ 四流 combine → collectLatest
  ③ resolveIndex：比较 SearchIndex.fingerprintOf(docs)
        同指纹 → 复用旧索引；不同 → SearchIndex.build（并置 isIndexing）
  ④ SearchIndex.search
        ├─ SearchScorer.matchType：名称（**含别名**）→ 拼音 → 位置 → 分类（命中即返回，顺序即优先级）
        ├─ SearchScorer.weightOf 取分 → 按分降序、同分按 lastModifiedAt 降序 → 截断
        └─ 仅 NAME 档给 highlightRange（经源下标映射回原串）
  ⑤ SearchHit → SearchResultUi（副标题「路径 · 最后确认」与 ⚠ 在此组装）→ SearchScreen → ItemRow
  ⑥ 另一条更慢的去抖通道 → recordIfUseful → ItemRepository.recordRecentQuery
        └─ RecentSearchDao.upsert + trim（上限裁剪）
  ⑦ FR-22 筛选（在 ④ 的结果上再过滤，与检索同一条 combine）：
        filters（分类 / 位置 / 状态）→ applyFilters
              ├─ 分类、状态：字段直接比对
              └─ 位置：subtreeIdsOf(rootId, tree) —— **含子层**（走父链，不用会随改名而变的名称路径）
        可选项 buildFilterChoices：分类 / 状态取自当前文档集，位置取整棵树（label 用 pathText 全路径）
        清空 = 三个集合一起置空；筛完为空时提示「可试试清空筛选」
```

检索文档怎么来：`ItemRepositoryImpl.observeSearchDocs`（三表 `combine`）→ `buildSearchDocs`（分类名查表；位置路径与路径拼音在此算好，路径拼音**按路径文本缓存、不落库**）→ `ItemEntity.toSearchDoc`。
P1 起 `buildSearchDocs` 还把 `alias_blob` 拆成别名列表并入文档 —— **别名与名称同档**（`MatchType.NAME`）参与检索。

## D｜详情、状态动作与「⋯更多」折叠区（FR-25 / 26 / 27 + 待归位）

```
SearchScreen / LocationBrowseScreen 点行 → goItemDetail(itemId) → ItemDetailRoute
  → ItemDetailViewModel.load → ItemRepository.getItemDetail
        ├─ ItemDao.findById
        ├─ 分类名（CategoryRepository 首个快照）
        ├─ locationTree ← LocationRepository.observeTree（供「移动到…」弹层）
        └─ buildLocationPath（LocationPath）—— 只作**首帧值**（页面不会先闪一个空面包屑）
  → init 的订阅（2026-10-13）：combine(observeTree, 本条 locationId) → 面包屑**实时派生**
        位置被**移动 / 改名 / 合并**时本条物品没有任何一列变化、refresh 不会被触发，
        靠的就是这条订阅（与 ItemEditViewModel 同一手法，两页口径一致）
  → refresh：两行时间文案 + 超期判定 + 分类名 / 别名 / 数量 / **备注** / 是否待归位
        → ItemDetailUiState → ItemDetailScreen
  → **动作全部走同一个 mutate 壳**（isBusy 挡重复、异常静默）：
        onConfirmStillHere   → confirmItem              （只写 lastConfirmedAt）
        onMarkGone           → setStatus(GONE)          （写 status + lastModifiedAt）
        onRestore            → restore                  （同上，回到 IN_STORAGE）
        onMarkToBePutBack    → setStatus(TO_BE_PUT_BACK)
        onPutBackToStorage   → setStatus(IN_STORAGE)    （不换位置，只改状态）
        onMoveTo(locationId) → ItemRepository.moveItem  （只换位置 + 刷 lastModifiedAt，
                                                          不动 status、不动确认时间）
  → 版面（2026-10-13 重排）：**物品信息常显在上**（分类 / 别名 / 数量 / 备注 / 最后变动），
        **是否存在在下**（最后确认 + ⚠ + 状态动作）—— 折叠区**只剩操作类**。
  → 「✏ 编辑」与「⋯更多」**都只做入口**：字段编辑一律落 P-ITEM-EDIT（见流程 H）。
        「⋯更多」本身 = **动作**：待归位↔归位 + 移动到… + 编辑入口
        移动到… 弹 LocationPickerSheet(allowCreate = false)（目标应是既有位置，不该顺手新建）
              **选中目标即关弹层**（2026-10-13 起）—— 与其余 6 个位置选择调用点同一口径；
              不关的话物品其实已换好位置、面包屑也已刷新，但弹层盖着，页面看不出任何变化
```

## E｜位置浏览（FR-01 / 02 / 03 / **04 / 06 / 21 / 28**）

```
HomeScreen「更多」→ 位置浏览 → goLocationBrowse(null) → LocationBrowseRoute
  → LocationBrowseViewModel.load(locationId)
  ① uiState = observeTree × 当前层物品 × currentId × 阈值  四流组合
        ├─ children：当前层的**直属**子级（下钻语义）
        ├─ items   ：当前层直属物品（根级不展示物品）
        └─ allRows ：整棵树（供删除时选迁移目标）
  ② 点子位置 → load(childId)         ← **页内切层（2026-10-13）**：只改 `currentId`，不压路由；返回键 / 「← 上一层」→ `goUp()`
  ③ 新建子位置 → onCreateChild → LocationRepository.create（同级末尾分配排序）
  ④ 改名 / 备注 → onRenameCurrent / onSetNoteCurrent → LocationDao.rename / setNote
        （**不动物品记录**：路径由父链实时拼装，改名后展示自动跟随）
  ⑤ 删除 → onDeleteCurrent(mode, targetId) → LocationRepository.delete
        在 TransactionRunner 单事务内：
          collectSubtreeIdsBottomUp（自底向上）
            └─ 档 1 MIGRATE：moveItems 整体迁移，状态不动
            └─ 档 2 ARCHIVE：moveItemsAndSetStatus(GONE) + 收容到内置哨兵
            └─ 随后逐条 locationDao.delete
        成功后 VM 回**父级**（2026-10-13 起；当前层已不存在，回根级等于让用户重新点回来）
  ⑥ **移动 / 合并（FR-04）**：
        onMoveCurrent(newParentId) → LocationRepository.move
              前置校验（§3.4-8）：目标不得在自身子树内
                    （用 LocationPath.isDescendantPath 判 ID 序列路径前缀，含相等）
              同事务：改 parent_id + **重写受影响子树的 path**
        onMergeCurrent(targetId)  → LocationRepository.merge
              source 的子位置与物品**全部改挂** target，随后 source 直接删
              （**不走删除两档** —— 那两档解决「物品往哪去」，此处物品已有明确去处）
              （**2026-10-13**：成功后 VM 同样回**父级** —— source 自己已不存在）
        两者都用 LocationMoveSheet 选目标（复用整棵树组件）
  ⑦ **临时位置标记（FR-06）**：onToggleTemporaryCurrent(flag) → LocationRepository.setTemporary
        → LocationDao.setTemporary。标记后该位置显示 TemporaryMark，其下物品在列表与 C-5 里带标记
  ⑧ **计数（FR-21）**：树行展示「本层 N 件 / 含子层共 M 件」
        ← LocationTreeRow.itemCount / subtreeItemCount（LocationRepositoryImpl.observeCounts）
        子孙范围走 `location.path` 的前缀**区间**查询（`LIKE` 表达式形态不走索引）
  ⑨ **按位置批量确认（FR-28）**：onConfirmAllInCurrent → ItemRepository.confirmByLocation(nodeId)
        → ItemDao.confirmActiveInSubtree（**含子层**；只写 last_confirmed_at、**不动** last_modified_at）
        确认前明示影响范围（N 件，含子层），返回值即「本次确认了 N 件」
  ⑩ **「＋ 往这里记一件」（P1 补齐的「批量录入入口」）**：onQuickAddHere → goQuickAdd(uiState.locationId)
        ← `PRD.md §6.1` 给 P-BROWSE 的职责里本就写着这一项，§6.2 跳转图也有 `BROWSE --> ADD`，
          此前**功能未落地**（缺入口，且 `QuickAdd` 路由无参、带不了位置），本次补齐
        入口 = 列表下方独立一行的主色按钮，**仅非根级**（根级不是一个位置，位置条无处预填）
        进 P-ADD 后位置条预选的就是**这一层**（预选优先级见流程 B 的 ①）
```


## G｜归纳统计（FR-33 / 29 / 38）

```
HomeScreen「更多」→ 归纳统计 → goStats → StatsRoute → StatsViewModel
  ① C-1（只出两块数字）：
        observeActiveItemCount ← ItemDao.observeActiveCount（`status != 'gone'`）
        observeLocationCount   ← LocationDao.observeUsableCount（`is_built_in = 0`）
        ⚠ **不用 observeTree 的长度**：buildTreeRows 会丢弃「父级缺失」的节点，
           树长可能小于真实位置数，统计数字不该受渲染降级影响
  ② C-4（FR-29 超期清单）：
        ConfigRepository.observeThresholdMonths() → flatMapLatest → ItemDao.observeOverdue(thresholdAt)
        阈值 = now − months × TimeUtil.MILLIS_PER_MONTH；**含「从未确认」**（last_confirmed_at IS NULL）
        「可观察流」正是「设置页改档 → 清单即时变」的实现方式（返回栈上的统计页不重建也生效）
  ③ C-5（FR-38 待归位清单）：
        ItemDao.observeToBePutBack —— `status = 'to_be_put_back'` ∪「位于用户标记过的临时位置」
        按**物品**去重（SQL 的 OR 天然去重，同一件不会出现两行）
  ④ 页内两态（**不新增路由**）：
        onOpenDetail(kind) → mode = DETAIL；onBackToCards() → mode = CARDS
        StatsScreen 的 BackHandler(enabled = isDetail) 第一次消费系统返回键 → 回卡片态
  ⑤ 明细行动作：
        C-4 行 onConfirmOverdue → ItemRepository.confirmItem（一步到位，不再二次确认）
        C-5 行 onPutBack(itemId, locationId) → ItemRepository.putBack
              一次操作同时「换位置」与「离开待归位」；
              弹 LocationPickerSheet(allowCreate = false)
```

## H｜物品编辑与别名 / 数量（P1-04）

```
ItemDetailScreen「✏ 编辑」/「⋯更多」→ goItemEdit(itemId) → ItemEditRoute → ItemEditViewModel
  ① load：getItemDetail → 填 loaded 快照（后续 diff 的基准）
  ② onAddAlias：归一化去重 → 不允许与名称相同 → 上限 5 → 不合格**静默丢弃**（不弹窗）
  ③ onSave：buildPatch 相对 loaded **只提交变化过的字段**
        ├─ 备注：空串 = 清空；null = 不改
        ├─ 分类：清空走 clearCategory 显式标志（与 categoryId 互斥）
        └─ 别名 / 数量 / 分类 / 备注
        → ItemRepository.updateFields → ItemDao.updateFields
              ├─ 别名变更时**同一条 UPDATE 内**重算 pinyin_full / pinyin_initial
              └─ **不刷 last_modified_at**（别名 / 数量 / 分类 / 备注都不改变「东西在哪、还在不在」）
  ④ isSaving + savedEvents：写成功后 Route 收到事件 → popBack
  ⑤ 数量：仅整数 ≥ 1（KeyboardType.Number，非法即 isError + 保存按钮禁用）
```

## J｜AI 录入旁路（V2 · AI-02 / AI-03；一句话 `V2-FR-02` / 语音一句 `V2-FR-10` / 一张照片 `V2-FR-11`）

**前置 = 设置页 AI 节**（P-SETTINGS）：总开关 + API Key + 本周期用量（次数 + token 合计）。开关**出厂默认关** —— 关着时
录入页**没有 AI 按钮、首页没有语音与拍照入口、零网络请求**，本链路整体不存在，行为与 v1.5 一致
（`V2-AI-PRD` §5 硬约束）。

**三个入口、一条下游**（解析与落库都在 `data/repository/AiIntake.kt`）：

- **录入页**（P-ADD）：名称框尾部的 AI 按钮；两个通道；单件回填主表单、多件逐条落库。
- **语音 AI 录入页**（P-VOICE-AI，`V2-FR-10`）：首页「🎤 语音AI记」**只做导航** → **独立页面**
  （`ui/screen/ai/`，**2026-10-09 由首页页内弹窗改**）页内话筒（`VoiceCapturePad`，
  无弹窗壳）长按**说话** / 抬手把**识别出的文字**交给模型 → **逐条确认弹窗**
  （与拍照页同一套；差别：**位置可改**）。一段话里含**不同位置的不同东西**、含**同一位置的多个东西**，
  都由「多行草稿 → 逐条确认」这一个机制覆盖；**位置不新建**：命中不到就降级到最近的已存在祖先。
  识别在**本机**完成、音频不出设备（走 `VoiceCapturePad` + `data/local/asr/`）—— 与录入页 P-ADD 的 🎤 是同一套。
  （2026-10-10 试过的「录音直送」因平台不受理音频输入已回退。）
- **拍照 AI 录入页**（P-PHOTO-AI，`V2-FR-11`／`V2-FR-13`）：首页「📷 拍照AI记」**只做导航** → **独立页面**
  （`ui/screen/ai/`，**2026-10-09 由首页页内展开面板改**）**先定位置、再挂照片、最后点识别**
  （顺序是硬口径：模型这一路**永不返回位置**，故无位置时识别键不可点）→ **逐条确认弹窗**
  （一件一弹，**2026-10-09 二次改**：三个出口 = 确认 / 放弃 / 关闭；**同日三次改**：确认 = **立刻弹下一件**，
  这一件的写库投给**应用级作用域的串行队列**（`@ApplicationScope` + `commitMutex`，离开页面仍跑完）；
  放弃 = 跳过这一件 / 关闭 = 放弃本次录入。**同日四次改**：弹窗抽成共用 `AiItemDialog`（与语音页同一份，
  差别仅位置：语音**可改**、本页**只读**））
  → **留在本页**（位置保留，可接着拍下一张）；一张图**不复制成 N 份**
  （`photo_path` 只存文件名，N 条共用同一文件 ⇒ 删图前判引用，且**写库在途时不许删**）。

```
① 触发（入口三选一）
     · 录入页名称框尾部 AI 按钮（可见性 = QuickAddUiState.aiEnabled ← AiSettingsRepository.observeEnabled）
        通道由「当前表单给了什么」决定：**有照片走照片通道**（照片由既有 PhotoInputRow 挂上），
        否则看名称框的文字走文字通道；两者都没有 → 只给一行提示
     · 首页「🎤 语音AI记」（可见性 = HomeUiState.aiEnabled ← **同一条** observeEnabled）
        → **导航进 P-VOICE-AI**（`goVoiceAiIntake`）：页内 VoiceCapturePad 长按说话 / 抬手出字
        → 识别出的**文字不落任何输入框**，直接 onSpokenText(文字)
        （页内那个临时测试输入框走同一个 onSpokenText）
     · 首页「📷 拍照AI记」（同一可见性）→ **导航进 P-PHOTO-AI**（`goPhotoAiIntake`）：
        **先** onLocationSelected（LocationPickerSheet）→ **再** onPhotoChanged（PhotoInputRow）
        → 最后 onRecognizePhoto(base64)
② 照片通道：**Compose 层**用 util/AiImageEncoder 把 filesDir/photos/<名> 编成裸 base64（IO 线程）
     → 传进 VM（本工程文件 IO 一律留在 Compose 层，VM 不持有 Context）
③ VM 侧前置判断（读的是**页内表单态**，故留在页面 VM，不进用例层）
     · 先判密钥（没配 → 「去设置页填」而不是「解析失败」）
     ⚠️ 照片通道的**位置前置**（V2-FR-13「位置先定后用」）：未选位置时**不调模型**，直接给行内提示
④ AiIntake.parseText(text, createMissingLayers) / parseSpokenText(text) / parsePhoto(base64)
     ← **三个入口共用这一步**（内部共用一个私有 `parseWith`，差别只有入参与「建不建未命中的层」）
     （语音页传 `createMissingLayers = false` ⇒ 位置降级不新建；录入页默认 `true` ⇒ 未命中层标「待新建」）
     · 位置清单取**全量**位置树、分类名单取全量分类（口径见 05-改动须知 §1-30）
     · 异常（网络 IO）在这一层收敛成 null；**协程取消原样放行**（否则 viewModelScope 的取消失效）
     ↓ AiGate.run(AiRequest(input, scene, categoryNames, locationPaths, imageBase64))
⑤ AiGate（唯一闸门）：必需内容 → 总开关 → 密钥 → 进程内 LRU（键 = 场景+输入+**图片指纹**+两清单）
     · **命中缓存** ⇒ 直接返草稿、**不发请求，但用量照计**（`countUsage(该条首次调用的 tokens)`）
     · **未命中** ⇒ → DeepSeekAiClient；**失败（非 2xx / 解析失败）返 null 且用量不计数**；成功才
       `countUsage(tokens)`（次数 +1 与 token 合计累加同一处；供应商没回 `usage` ⇒ 只计次数）
     ⚠️ 命中也要计 ⇒「共消耗」是 **AI 产出量**口径（同一结果被重放也照算），**高于**供应商账单、不可对账
⑥ DeepSeekAiClient：AiPrompt 四段拼接 → POST（response_format = json_object）→ DraftParser.parse
     → List<AiDraft>（null=失败；空列表=成功但没识别出 —— 两者文案不同）
⑦ AiIntake 组装草稿行：LocationPathMatcher 逐层匹配 → AiDraftRow（命中 id / 待新建层名 / 分类 id / 展示文本）
     ↓ 两条呈现路径（同一份 AiDraftRow）
     · 录入页：AiState.Draft(rows) → AiStatusSection → AiDraftCard
       （**页内一段，不是弹层**；默认全选，可逐行取消；**AiDraftCard / AiStatusSection 唯一宿主 = 录入页**）
     · 语音 / 拍照 AI 录入页：入队 → 逐条弹窗 AiItemDialog（一件一弹；可改名称 / 分类 / 备注；
       语音**位置可改**、拍照**位置只读**）
       ※ 两页**都不产生** AiState.Draft，页内状态只剩「识别中 / 失败」两行
       ※ **点确认即刻前进**：`advance()` 与「在途计数 +1」同帧落定，写库投给 appScope 上的串行队列
         （锁内 FIFO）⇒ 弹窗不为写库停帧；上一件在点击那一帧就离开了弹窗 ⇒ **重复点确认不可能**
⑧ 用户确认
     · 录入页 1 件 → **走既有 setter 回填主表单**，卡片收掉；仍由用户点「保存并继续」才落库
     · 录入页多件 → AiIntake.commitRows：逐条 createItemQuick；位置 = 命中 id / 按父链逐层 create
              （**同一批内复用节点**）/ 兜底 = 用户已选位置；**photoPath = null**（一图不复制成 N 份）；
              计数 = 实际写成功条数
     · 语音页 / 拍照页 → **每确认一件调一次 commitRows(listOf(row))**（`fallbackLocationId = null`，
              `photoPath` = 本轮快照的文件名，语音页恒 null）：**第一件落库成功即清页面态 `photoName`**
              （图已归库，页面不再持有）；放弃 = 不入库也不计数；关闭 = 丢弃队列里剩下的件（**已确认的留在库里**）
     ※ **位置兜底不再有「无位置即跳过」一说**：语音行命中不到任何位置时进弹窗、**确认置灰**，用户可就地
       补位置解禁（`AiItemEdit.canConfirm` = 名称非空 ∧ 有位置）
⑨ 未点确认前**库中零新增**（V2-FR-04）；录入页点「忽略」→ 卡片收掉、主表单与库都不变；
   两 AI 页点「关闭」→ 弹窗收掉、未处理件丢弃（已落库的不回收）
```

**失败只有一条降级路径**（`V2-FR-07`）：任何环节失败 → `AiState.Failed(原因)` → 页面映射成**一行行内
提示**（`strings.xml` 的 `ai_entry_fail_*`），**不弹窗、不阻塞、主表单不动**；用户可继续手工录入。

## 关键边界

各条链路（A~J）里最容易搞混的是「谁持有哪份状态」。**每一份状态只有一个持有方**；出现第二份可独立修改的同源状态即为缺陷。

| 状态 | 唯一持有方 |
|---|---|
| 物品 / 位置 / 分类 / 配置的全部可变状态 | `data/local/`（Room） |
| 内置常量与首启默认树（只读） | `data/memory/BuiltInData.kt` |
| 检索文档（含路径与路径拼音） | `ItemRepositoryImpl.observeSearchDocs` 构建期由三表 `combine` 派生，**不落库** |
| 检索索引 | `SearchViewModel.resolveIndex`（指纹相同即复用旧索引） |
| 录入页状态与 `canSave` | `QuickAddViewModel`（位置必填的唯一判定点） |
| 录入页的**初始位置** | 进页那一次由路由参数（`QuickAdd.locationId`）经 `QuickAddViewModel.initialize` 落定，**只跑一次**；此后归 `QuickAddUiState.selectedLocationId` |
| 详情页可见状态与动作串行化 | `ItemDetailViewModel`（`isBusy` 挡重复动作） |
| 当前浏览层 | `LocationBrowseViewModel`，由路由参数 `locationId` 驱动 |
| 状态动作的写入 | `ItemRepositoryImpl.confirmItem` / `setStatus` / `restore`，行为经 `ItemDetailViewModel.mutate` |
| `NavController` 与返回栈 | 仅 `MainActivity` 创建 → `LocalNavController` 下发 |
| 系统栏避让 | 仅 `RouteHandler` 的 `NavHost`，页面不各自处理 |
| 检索筛选条件（三维） | `SearchViewModel.filters`（页面内状态，**不落库、不进路由**） |
| 统计页卡片态 / 明细态 | `StatsViewModel` 的 `mode`（**不进路由**；系统返回键第一次由 `StatsScreen` 的 `BackHandler` 消费） |
| 超期阈值 | `app_config`（Room）；`ConfigRepositoryImpl.observeThresholdMonths` 是唯一订阅入口，C-4 与设置页都从它读 |
| 物品编辑页的待提交改动 | `ItemEditViewModel`（`loaded` 快照是 `buildPatch` 的 diff 基准） |
| 字段写入（别名 / 数量 / 备注 / 分类） | `ItemRepositoryImpl.updateFields`，行为经 `ItemEditViewModel.onSave` |
| 位置移动 / 合并的写入 | `LocationRepositoryImpl.move` / `merge`（**单事务**内改 `parent_id` 并重写子树 `path`） |
| 归位与移动的写入 | `ItemRepositoryImpl.putBack`（换位置 + 离待归位）/ `moveItem`（只换位置） |
| 分类增删改的写入 | `CategoryRepositoryImpl.create` / `rename` / `delete`（内置保护在仓库层） |
| AI 状态机（`AiState` 五态） | **各页自己持有**（`QuickAddViewModel` / `VoiceAiIntakeViewModel` / `PhotoAiIntakeViewModel` —— 它本来就是页内 UI 态）；「失败原因 → 文案」的映射在共用 `AiFailText`。⚠️ **两条 AI 页都不产生 `AiState.Draft`**，只用到 `Hidden` / `Idle` / `Parsing` / `Failed`（确认卡形态只剩录入页） |
| 两条 AI 页的**结果段**（队列 / 逐条进度 / 汇总 / 在途计数 / 轮次号） | `ui/component/ai/AiItemQueue`（**每页 VM 各持一份实例**，状态 = `AiQueueState`）；**确认即落库**，故队列里只有「还没处理完的件」，已确认的在库里。页面级差异全由回调吃掉（`photoPathProvider` / `onRoundStarted` / `onQueueEnded` / `onCommitted`） |
| AI 的可用性（总开关 + 密钥） | `app_config.ai_enabled`（缺省按关）+ 密钥密文落应用私有 `SharedPreferences`；**唯一读写入口是 `AiSettingsRepository`** —— 录入页、语音页、拍照页、首页与设置页订阅**同一条** `observeEnabled`，各页不会读到两个值 |
| AI 调用的放行与去重 | `AiGate`（唯一闸门；LRU 只在**进程内存活**，不落盘 —— 重启即失效，避免把用户输入长期留存） |

链路级还有两条不变量：**索引失效由 Repository 兜底过滤**（`ItemRepositoryImpl.filterActive`，不由页面判定）；**展示类派生一律在 ViewModel 组装完成**（Screen 拿到的是字符串与布尔，不是需要再算的原始值）。

其余跨链路口径（拼音落点、时间戳矩阵、事务边界、哨兵不外露等）见 [`05-改动须知.md`](05-改动须知.md) §1。
