# 界面层 · 文件清单

## 文档职责

本文由 [`00-索引.md`](00-索引.md) 分出，记录**界面层的文件清单**：入口与主题 / 导航 / **9 个页面**（Route + Screen + ViewModel 成组）/ 复用组件，
每项给「职责 + 关键符号」——定位时直接搜符号名，比按行号跳更抗漂移。
分层与依赖方向、任务定位索引、目录索引见 `00-索引.md`；数据、检索、构建不在此。

## 阅读入口

- **何时读**：任务定位索引指向本文件，或需要确认某个 UI 文件的职责与关键符号时。
- **前置约束**：[`../实现约束.md`](../实现约束.md) §1、§3（动 UI 前必读）；[`../../AGENTS.md`](../../AGENTS.md)。
- **不适用**：只需知道「某功能在哪个文件」时，`00-索引.md` §1 已能回答，不必读本文件。

## 1. 入口与主题

| 文件 | 职责 | 关键符号 |
|---|---|---|
| `MainActivity.kt` | 唯一 Activity：建 NavController 并下发、边到边、**窗口层锁浅色** | `attachBaseContext`（`uiMode = NIGHT_NO`）、`onCreate`（`enableEdgeToEdge()` + `LocalNavController provides rememberNavController()`） |
| `ShounaApplication.kt` | Hilt 入口（空实现，Manifest `android:name` 指向它） | `@HiltAndroidApp` |
| `ui/theme/Theme.kt` | 永久浅色（动态取色锁 `dynamicLightColorScheme`）＋ 字号锁 `fontScale = 1f` | `ShounaTheme`、`LightColorScheme` |
| `ui/theme/Color.kt` / `Type.kt` | 静态配色、排版 | `Purple40` / `PurpleGrey40` / `Pink40`、`ShounaTypography` |

> 浅色与字号是**三层锁**：Compose 侧 `Theme.kt`、窗口侧 `MainActivity.attachBaseContext`、资源侧无 `res/values-night/`。改一处必须核另两处（见 [`05-改动须知.md`](05-改动须知.md)）。

## 2. 导航

| 文件 | 职责 | 关键符号 |
|---|---|---|
| `ui/navigation/ShounaRoute.kt` | **9 个** `@Serializable` 路由键（纯声明，不含 Composable） | F1 的 `Home` / `QuickAdd` / `Search(initialQuery)` / `ItemDetail(itemId)`、P0 的 `LocationBrowse(locationId)`、P1 的 `Stats` / `ItemEdit(itemId)` / `Settings` / `CategoryManage` |
| `ui/navigation/RouteHandler.kt` | 唯一 `NavHost`（`startDestination = Home`）+ 9 个页面注册 + `LocalNavController` + 容器级系统栏避让 + **页面切换过渡覆盖**（`enter` / `exit` 统一 `tween(NAV_TRANSITION_MILLIS)`，取代库默认的 `tween(700)`） + **10 个导航动作**（9 个 `goXxx` + `popBack`） | `LocalNavController`、`RouteHandler`、`NAV_TRANSITION_MILLIS`、`goHome` / `goQuickAdd` / `goSearch` / `goItemDetail` / `goLocationBrowse` / `goStats` / `goItemEdit` / `goSettings` / `goCategoryManage` / `popBack` |

**P1 的两条路由边界**（`ARCHITECTURE-P1` §8.1-15 / §8.1-16）：**统计下钻不新增路由** —— 卡片态 / 明细态是同一个 `Stats` 目的地的页内两态；**分类管理有独立页**（`prd/07` §6.1 未给），由 P-SETTINGS 内的入口进入。P1 的 4 条与既有 5 条注册在**同一张 `NavHost`** 上，不引入嵌套图。

**接线规则**（改页面先看这条）：`NavController` 只在 `MainActivity` 创建一次 → 经 `LocalNavController` 下发 → **只有 `XxxRoute` 读它**，用来把 `onXxx` 接到 `goXxx` / `popBack`；`XxxScreen` 一律不读。

## 4. 复用组件（`ui/component/`，全部无状态）

| 文件 | 职责 |
|---|---|
| `ShounaSearchBar.kt` | 首页只读形态 / 搜索页可编辑形态共用 |
| `ItemRow.kt` | 物品行：名称 + 高亮 + 可选副标题 + 可选 ⚠ + 可选「长按复制路径」 |
| `CategoryChips.kt` | 分类 chips，再次点击取消选中；**消费 `observeCategories` 的动态列表**（不再读内置常量） |
| `RecentQueryChips.kt` | 最近搜索词（仅搜索页空态；为空整块不渲染） |
| `RelativeTimeText.kt` / `OverdueMark.kt` | 相对时间行 / 超期 ⚠ 标记（判定都由 VM 下传） |
| `LocationBreadcrumb.kt` / `LocationTreeItem.kt` | 面包屑（长按复制）/ 位置树一行（展开态由调用方持有；行内含 `TemporaryMark` 与「本层 / 含子层」两个计数） |
| `LocationPickerSheet.kt` | 位置选择弹层：内嵌整棵树 +「＋ 新建位置」+ 最近使用。**`allowCreate = false` 时隐藏新建入口** —— 迁移 / 归位 / 移动目标场景用它（目标是既有位置，不该顺手新建） |
| `LocationMoveSheet.kt` | **P1**：移动 / 合并的目标选择弹层。与上者的差别是**语义**（选「新父级 / 合并到哪」而非「把东西放哪」）且**必须排除自身子树**；两处在 `LocationBrowseScreen` 各挂一次 |
| `TemporaryMark.kt` | **P1**：临时位置标记（FR-06）。三处复用：位置行、该层物品行、统计 C-5 明细行 |
| `StatCard.kt` | **P1**：统计卡片（C-1 只出两块：物品总数 / 位置总数） |
| `AliasEditor.kt` | **P1**：别名 chips 编辑（增删、上限与去重口径由 `ItemEditViewModel` 判定后下传） |
| `FilterChips.kt` | **P1**：单排可多选的筛选 chips（点击切换、再次点击取消）。搜索页三维各挂一次；**不复用 `CategoryChips`** —— 后者是「单选分类」语义 |
| `EmptyState.kt` | 首页无物品 / 搜索无结果 |

**复用边界**：组件只接渲染参数与回调；剪贴板（`LocalClipboardManager`）属平台 UI 能力，允许留在组件层，但**判定类逻辑**（是否超期、路径文本）必须由 VM 传入。
