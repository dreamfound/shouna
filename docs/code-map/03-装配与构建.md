## 2. 建库与种子时序

1. 首个 `ShounaDatabase` 实例被注入时 `Room.databaseBuilder(...).addCallback(SeedCallback()).addMigrations(Migrations.MIGRATION_1_2, Migrations.MIGRATION_2_3)` 建库；
2. **全新安装**：`ShounaDatabase.onCreate` → `SeedCallback.onCreate`（裸 `execSQL`，因为此刻拿不到 DAO）写入：哨兵位置 → 默认位置树 6 节点（**逐列 INSERT，`path` 取自 `BuiltInData.SEED_LOCATION_PATHS`**）→ 8 条内置分类 → 超期阈值；
3. **存量库升级**（`version 1 → 2 → 3`）：**不走 `onCreate`**，逐级走迁移链 —— `Migrations.MIGRATION_1_2` 加 `location.path` 列 → 递归 CTE 回填 → 建 `index_location_path`；`Migrations.MIGRATION_2_3` 只加 `item.photo_path`（可空 / 无默认 / 无索引）；
4. 两条路径**必须产出同一形态的 `path`**，由 `androidTest` 的 `MigrationsTest` 双向验证（升级库按回填结果、新建库按 `parent_id` 链独立推导）；
5. 数据库已存在且版本已是最新时**既不写种子也不跑迁移** → 不会覆盖用户数据。

改首启数据 = 改 `BuiltInData` 常量；改种子语句 = 改 `SeedCallback`。两者必须同步（常量是唯一来源，`SeedCallback` 只负责写）。
**迁移只增不改**：`version` 一旦发出就不许回头改它的迁移体（已升级的库不会再跑一遍）；要修正只能追加 `MIGRATION_n_n+1`。

## 3. 构建与版本

| 文件 | 要点 |
|---|---|
| `gradle/libs.versions.toml` | **版本真源**，含 pin 原因注释（如 `core-ktx` 不得升、`hilt-navigation-compose` 钉 1.3.0、`room` / `pinyin4j` 的选型理由） |
| `app/build.gradle.kts` | `namespace = com.dream.shouna`、SDK 版本、Compose、**core library desugaring**（使 `minSdk 24` 可用 `java.time`）、KSP 的 `room.schemaLocation` 与 `room.generateKotlin`、依赖清单、**`splits.abi` 拆包**（2026-10-10 起：Vosk 的 `libvosk.so` 覆盖四架构、未压缩合计约 39.7 MB ⇒ 四个都留、各自出包；`isUniversalApk = false`。注意拆包**不复制 assets** ⇒ 每个分包仍各带一份 42 MB 的语音模型） |
| `app/build.gradle.kts` 的 `buildTypes` | **release 开 `isMinifyEnabled` + `isShrinkResources`；debug 明确不开**。取舍见本节末 |
| `app/proguard-rules.pro` | release 的 R8 规则。两个反射入口必须显式保留：`@Serializable` 路由类的 `Companion.serializer()`（导航按 `T.Companion.serializer()` 取 `KSerializer`）× 当前规则形状；Room `@Database` 子类。**不得保留 `androidx.compose.runtime.**`** —— Compose 自带 consumer rules，整包 keep 会让压缩基本失效 |
| `app/build.gradle.kts` 的 `sourceSets` | **P1-01 新增**：`getByName("androidTest").assets.srcDir("$projectDir/schemas")` —— 把导出的 schema 目录挂进 androidTest 资产，让 `MigrationTestHelper` 按「数据库类全名 / `<version>.json`」读到 v1 / v2 / v3 结构（迁移测试据此构造 v1 存量库并覆盖 v1 → v3 跨级升级）。**只是资产挂载，不新增依赖** |
| `settings.gradle.kts` / `build.gradle.kts` / `gradle.properties` | 仓库源与工具链；**不新增仓库** |
| `app/build.gradle.kts` 测试块 | 单测（JVM）与仪器测试（`androidTestImplementation(room-testing)`）的依赖分界 |

**KSP 的两次使用**：Hilt（仅服务 Hilt 注解处理）与 Room（生成 DAO 实现 + 导出 schema）。两者都用 KSP，**不要退回 kapt**。

**为什么 debug 不开压缩**（2026-09-30 开启 release 压缩时的实测结论）：androidTest 变体的 R8 跟随被测 `buildType` 一起启动，而压缩后的 **app APK** 会裁掉测试代码依赖的 kotlin-stdlib 入口 —— instrumentation 启动即 `ClassNotFoundException: kotlin.LazyKt`。给测试 APK 单独挂 `testProguardFiles` 并写 `-dontshrink/-dontobfuscate/-dontoptimize` **无效**，因为缺失的类在 app APK 里，测试 APK 补不了。另：压缩会一并牺牲断点、真实行号与 Layout Inspector，且每次 debug 构建都要付 R8 全量耗时。**若将来确需"日常也跑压缩包"，正确做法是用 debug 签名签 release 包覆盖安装（数据不丢），而不是打开 debug 的 minify。**

## 4. Manifest 与资源

| 文件 | 要点 |

| `app/src/main/AndroidManifest.xml` | **两条 `uses-permission`**：`RECORD_AUDIO`（FR-18 语音，P1 起）+ `INTERNET`（V2 · AI-01，**只许被 `data/remote/ai/` 使用**）。**刻意不声明** `CAMERA`（走系统相机 Intent 时声明反而要求已授权）。`allowBackup="false"`；Application 与唯一 Activity 注册；Activity `windowSoftInputMode="adjustResize"`；**`<queries>` 声明两条**：`ACTION_IMAGE_CAPTURE`（Android 11+ 包可见性 —— 不声明则系统相机解析不到）与 **`android.speech.RecognitionService`**（**2026-10-10 补**：同样受包可见性过滤，缺声明则 `SpeechRecognizer.isRecognitionAvailable()` 恒 false、话筒永不绘制；见 [`../实现约束.md`](../实现约束.md) §7-4）；FileProvider（`${applicationId}.fileprovider`，路径白名单见 `res/xml/file_paths.xml`） |

| `res/values/`（`colors.xml` / `strings.xml` / `themes.xml`） | 应用名与主题；**无 `values-night/`**（已删，属浅色锁的一部分）。注意：**P1 新增页面的文案未进 `strings.xml`**，按既有代码沿用中文字面量；**V2 的 AI 文案是这条惯例的例外 —— 一律集中在 `strings.xml`**（前缀 `settings_ai_*` / `ai_entry_fail_*` / `ai_card_*` / `ai_home_*`，`strings.xml` 内亦有对应注释），新增 AI 文案照此进资源，别硬编码 |
| `res/xml/`（`backup_rules.xml` / `data_extraction_rules.xml` / `file_paths.xml`） | 前两者 = 备份规则（与 `allowBackup=false` 配套）；`file_paths.xml` = FileProvider 的路径白名单，**只暴露 `filesDir/photos/`**（FR-16 拍照结果的落点，Manifest 的 `@xml/file_paths` 指向它） |
| `res/drawable/`、`res/mipmap-anydpi*/` | 启动图标（自适应图标） |

## 5. 改动连带关系（改这几处时的固定配对）

| 改动 | 连带必须一起动 |
|---|---|
| 加 / 改字段 | `entity/*` → `ShounaDatabase` 表清单 → 相关 `*Dao` → `domain/model/*` → `repository/*Impl` 的转换函数 → `app/schemas/` |
| 加页面 | `ShounaRoute.kt` → `RouteHandler.kt` 注册 → `ui/screen/<页>/` 三件套 |
| 加依赖 / 升版本 | `libs.versions.toml` → `app/build.gradle.kts`（并核对 pin 注释里的兼容理由） |
| 改混淆规则 / 动 `buildTypes` | 重跑 `assembleRelease` → **装机冒烟**（R8 的破坏只在运行时暴露，编译通过远远不够）→ 顺带核 `app/build/outputs/mapping/release/` 是否正常产出 |
| 动表结构 | `entity/*` → `ShounaDatabase`（`version` 加一）→ `Migrations.kt` 追加 `MIGRATION_n_n+1` → 相关 `*Dao` → 构建后 KSP 生成新的 `<version>.json`。**当前 `version = 3`**；只要既有库可能带着旧版本，就必须写迁移，**不得启用 `fallbackToDestructiveMigration`** |
| 加 / 改 **AI 出网调用**（V2） | 出网代码只能落在 `data/remote/ai/`；调用**必须**经 `data/repository/AiGate.kt`（开关 → 密钥 → 缓存 → 调用）；新增权限或新厂家 → 同步 `AndroidManifest.xml` / `di/AiModule.kt`；核对 [`../实现约束.md`](../实现约束.md) §7-5 与 `data/remote/ai/AiVendor.kt` |
