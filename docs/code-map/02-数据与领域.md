# 数据与领域 · 文件清单

## 文档职责

本文由 [`00-索引.md`](00-索引.md) 分出，记录**数据与领域层的文件清单**：仓库接口与实现 / 持久化（表 · DAO · 事务）/ 内置常量 / 领域模型与检索 / 工具，
每项给「职责 + 关键符号」。
分层与依赖方向、任务定位索引见 `00-索引.md`；UI 与构建不在此。

## 阅读入口

- **何时读**：任务定位索引指向本文件，或需要确认某个数据层文件的职责、关键符号与接口口径时。
- **前置约束**：[`../实现约束.md`](../实现约束.md) §2（状态与数据边界）、§5（schema 与迁移）；[`../../AGENTS.md`](../../AGENTS.md)。
- **不适用**：只需知道「某功能在哪个文件」时看 `00-索引.md` §1；要看跨文件链路走向看 [`04-流程链路.md`](04-流程链路.md)。

## 1. 仓库层（`data/repository/`）

| 文件 | 职责 | 关键符号 |
|---|---|---|
| `ItemRepository.kt` | 接口：录入 / 摘要流 / 检索文档流 / 最近搜索词 / 详情 / 三个状态动作；**P1 扩**：补丁式字段更新、含子层批量确认、重名查重、归位、移动、计数与两个清单流 | `createItemQuick`、`observeItemSummaries`、`observeSearchDocs`、`observeRecentQueries`、`recordRecentQuery`、`getItemDetail`、`confirmItem`、`setStatus`、`restore`、`updateFields`、`confirmByLocation`、`findSimilar`、`putBack`、`moveItem`、`observeActiveItemCount`、`observeOverdueItems`、`observeToBePutBackItems`；补丁表 `ItemFieldPatch`（同文件：`categoryId` / `clearCategory` / `aliases` / `quantity` / `note`，**不含「去向备注」** —— 无对应列） |
| `ItemRepositoryImpl.kt` | 实现；**拼音在写入时派生并落列**（改别名时**同一条 UPDATE 内**重算）；分类名与位置路径**构建时实时拼入**（不冗余落库）；**只有状态 / 位置变化才刷 `last_modified_at`**；**录入时三个时间列同值**（`createdAt` = `lastModifiedAt` = `lastConfirmedAt`，即「录入即一次确认」，2026-09-30 起） | `buildSearchDocs`、`buildLocationPath`；同文件 `internal` 转换：`deriveNormalizedName` / `filterActive` / `toEntity` / `toDomain` / `ItemEntity.toSearchDoc` |
| `LocationRepository.kt` | 接口：树 / 子级 / 该层物品 / 新建 / 改名 / 备注 / **删除两档** / 最近使用；**P1 扩**：移动 / 合并 / 临时标记 / 件数流 / 位置总数流 | `observeTree`、`observeChildren`、`observeItemsIn`、`create`、`rename`、`setNote`、`delete`、`recentUsed`、`touchLastUsed`、`move`、`merge`、`setTemporary`、`observeCounts`、`observeLocationCount`、`LocationDeleteMode`（`ARCHIVE` / `MIGRATE`）、`LocationCounts`（本层 / 含子层两个数） |
| `LocationRepositoryImpl.kt` | 实现；跨表写走单事务、**自底向上删子树**、对外**过滤内置哨兵**；移动 / 合并**同事务重写受影响子树的 `path`** | `collectSubtreeIdsBottomUp`、`isInSubtree`；同文件 `buildTreeRows`（纯函数，JVM 可测） |
| `CategoryRepository.kt` / `CategoryRepositoryImpl.kt` | P0 只读 → **P1 扩为可写**（FR-44）；8 条内置分类由种子写入，**内置可改名不可删**（删除由仓库层挡，不靠 UI） | `observeCategories`、`create`、`rename`、`delete` |
| `ConfigRepository.kt` / `ConfigRepositoryImpl.kt` | 超期阈值（FR-27 / 29 / 47）：一次读（解析失败回落默认值，不阻断详情页）+ **可观察读**（改档即时驱动 C-4）+ 写 | `thresholdMonths`、`observeThresholdMonths`、`setThresholdMonths` |

**接口形态口径**：接口只暴露领域模型与 `Flow`，不返回 `*Entity`、不泄漏 DAO；`internal` 的转换函数留在 `Impl` 同文件，供单测直接调用。改实现（数据源、事务）时**接口不动**。

## 2. 持久化（`data/local/`）

| 文件 | 职责 | 关键符号 |
|---|---|---|
| `ShounaDatabase.kt` | 5 张表、**`version = 2`**、导出 schema、5 个 DAO 访问器；类注释里登记**不建的表** | `ShounaDatabase`、`NAME`、`itemDao()` / `locationDao()` / `categoryDao()` / `recentSearchDao()` / `configDao()` |
| `Migrations.kt` | **P1 新增**：迁移链唯一入口，本工程**首个真实迁移** `1 → 2`（`ALTER TABLE` + 递归 CTE 回填 + 建索引，三步在同一个 `Migration` 内）；**不启用** `fallbackToDestructiveMigration` | `Migrations.MIGRATION_1_2`；挂载点 `di/DatabaseModule.provideShounaDatabase` 的 `addMigrations` |
| `SeedCallback.kt` | **仅建库时**写种子：哨兵 + 默认位置树（**逐列 INSERT，含 `path`**）+ 8 分类 + 阈值（用裸 SQL，`onCreate` 阶段拿不到 DAO） | `SeedCallback.onCreate`、`seedLocations` / `seedCategories` / `seedConfig` |
| `Converters.kt` | `ItemStatus` ↔ 稳定 code；未知 code 兜底为在存 | `fromItemStatus`、`toItemStatus` |
| `TransactionRunner.kt` | 事务边界抽象，使跨表写逻辑可在 JVM 单测覆盖 | `TransactionRunner.run`、`RoomTransactionRunner` |
| `entity/ItemEntity.kt` | `item` 表；FK `location RESTRICT` / `category SET_NULL`；索引 `location_id`、`category_id`、`normalized_name`；`alias_blob`（`\u001F` 分隔）与 `quantity` **P1 起真正写入** | `ItemEntity` |
| `entity/LocationEntity.kt` | `location` 表；自引用 FK RESTRICT；索引 `parent_id` + **`path`（P1 新增）**；`path` 是 **ID 序列**（`/根id/…/自身id/`，含自身）；`is_temporary` P1 起可写 | `LocationEntity`（`path` 的 `defaultValue = "''"` 必须与迁移的 `DEFAULT ''` 逐字一致） |
| `entity/CategoryEntity.kt` / `RecentSearchEntity.kt` / `AppConfigEntity.kt` | 分类 / 最近搜索词 / 配置三表 | 同名 `…Entity` |
| `dao/ItemDao.kt` | `item` 读写；**更新一律返回受影响行数**（不「先查再写」）；P1 起含补丁式字段更新、子树批量确认、超期与待归位清单、归位 / 移动 | `observeActiveCounts`、`updateLastConfirmedAt`、`updateStatus`、`moveItems`、`moveItemsAndSetStatus`、`countIn`、`updateFields`、`confirmActiveInSubtree`、`observeOverdue`、`observeToBePutBack`、`observeActiveCount`、`putBack`、`moveItem`、`LocationItemCount` |
| `dao/LocationDao.kt` | `location` 读写；`parent_id IS :parentId` 同时服务根级与子级；P1 起管 `path` 写读与子树查询 | `childrenOf`、`siblings`、`allUsable`、`recentUsed`、`rename`、`setNote`、`touchLastUsed`、`updateParentAndPath`、`updatePath`、`subtreeOf`、`descendantsOf`、`setTemporary`、`observeUsableCount` |
| `dao/CategoryDao.kt` | 分类读写；**P1 由只读扩为可写**（删只删非内置） | `observeAll`、`insertAll`、`count`、`insert`、`maxSortOrder`、`rename`、`deleteCustom` |
| `dao/RecentSearchDao.kt` | 最近搜索词：REPLACE 去重 + 上限裁剪 | `observeRecent`、`upsert`、`trim`、`RECENT_SEARCH_LIMIT` |
| `dao/ConfigDao.kt` | 配置键值读写；**P1 加可观察读**（支撑阈值即时生效） | `get`、`observe`、`put`、`KEY_THRESHOLD_MONTHS`、`DEFAULT_THRESHOLD_MONTHS` |

**DAO 层的两条约定**：① 读路径一律 `Flow`，写路径一律 `suspend`；② 单表更新不查后写，靠返回行数判断命中。跨表写不在 DAO 里做，交给仓库 + `TransactionRunner`。

## 3. 内置常量（`data/memory/BuiltInData.kt`）

唯一定义源，全部只读，`SeedCallback` 在建库时写入库中。

| 符号 | 内容 | 口径区分 |
|---|---|---|
| `UNSPECIFIED_LOCATION` / `UNSPECIFIED_LOCATION_ID` | 1 条哨兵「未指定位置」 | **系统保留位**：不进选择器与浏览页、不可删，只为「删位置档 2」的收容 |
| `BUILT_IN_LOCATIONS` | 仅哨兵 1 条 | 与下面区分清楚 |
| `BUILT_IN_CATEGORIES` / `BUILT_IN_CATEGORY_COUNT` | 8 条分类常量（chips 排列顺序 = `sortOrder`） | 名称取自 PRD 举例并补足到 8 条 |
| `DEFAULT_LOCATION_TREE` / `DEFAULT_ROOT_LOCATION_ID` | 首启默认位置树 6 节点（根 1 + 子 5） | **用户可见**：可改名、可删除，删光后仍可新建（不构成录入死锁） |
| `SEED_LOCATION_PATHS` | **P1 新增**：位置 `id → ID 序列 path` 的映射（写库前置计算） | 在常量层算而不是在 `SeedCallback` 里算，是因为 `path` 是**迁移与建库两条路径必须同形**的字段 —— 口径放一处，两边都从它取 |

## 4. 领域模型与检索（`domain/`）

| 文件 | 职责 | 关键符号 |
|---|---|---|
| `model/StoredItem.kt` | 物品领域模型（**不带**拼音列 —— 拼音只存在于 `ItemEntity`）；P1 起含 `aliases`（由 `aliasBlob` 拆出）与 `quantity` | `StoredItem` |
| `model/Location.kt` / `model/Category.kt` | 位置 / 分类；`Category.isBuiltIn` 是「内置可改名不可删」的判据 | `Location`、`Category` |
| `model/ItemStatus.kt` | 三态、稳定 code、`isActive` | `IN_STORAGE` / `TO_BE_PUT_BACK` / `GONE`、`fromCode` |
| `model/ItemDetail.kt` | 详情展示模型（物品 + 分类名 + 位置路径） | `ItemDetail` |
| `model/LocationTreeRow.kt` | 树行派生模型（位置 + 深度 + 路径 + 直属件数 + **含子层件数**），**不落库** | `LocationTreeRow`（`itemCount` / `subtreeItemCount` / `pathText`） |
| `search/SearchDoc.kt` | 索引文档：由三表联合派生；**逐字段说明拼音来源**（物品名拼音=持久化列，位置路径拼音=构建时派生）；**P1 起并入别名** | `SearchDoc` |
| `search/SearchIndex.kt` | 遍历 + 排序 + 截断；指纹用于复用索引 | `search`、`build`、`fingerprintOf` |
| `search/SearchScorer.kt` | 命中判定（**判定顺序即优先级**）、权重取值、高亮区间换算；**别名与名称同档**（`MatchType.NAME`） | `matchType`、`weightOf`、`highlightRange`、`score` |
| `search/SearchConfig.kt` | 检索上限与四档权重的真源（默认参数） | `limit`、`nameWeight` / `pinyinWeight` / `locationWeight` / `categoryWeight` |
| `search/MatchType.kt` / `search/SearchHit.kt` | 命中档位 / 命中结果（含高亮区间，可空） | — |

**纯 Kotlin 约束**：本目录不依赖任何 Android 框架类 —— 因此检索与路径逻辑都能在 JVM 单测里直接跑（含微基准）。

## 5. 工具（`util/`）

| 文件 | 职责 | 关键符号 |
|---|---|---|
| `TextNormalizer.kt` | 归一化（全角→半角、大小写、空白折叠）；高亮用的源下标映射 | `normalize`、`containsNormalized`、`collapseWhitespace`、`normalizeWithSourceIndex`、`toHalfWidth` |
| `PinyinUtil.kt` | 拼音派生：全拼 / 首字母（多音取默认、非汉字原样、输出再归一化） | `full`、`initial`、`keys` |
| `TimeUtil.kt` | 时间真源：当前毫秒、相对短语、超期判定；**时间戳矩阵记在类注释**；`MILLIS_PER_MONTH` 是阈值换算的公开常量（`isOverdue` 与超期清单查询共用同一口径） | `nowMillis`、`relativeConfirmText`、`relativeText`、`isOverdue`、`NEVER_CONFIRMED`、`MILLIS_PER_MONTH` |
| `LocationPath.kt` | **两种路径并列，别混**：名称路径（父链派生、**不落库**，用于面包屑与检索维度）；**ID 序列路径**（落 `location.path`，用于子树范围查询） | `segments`、`format`、`textOf`、`textsOf`；`buildIdPath`、`isDescendantPath`、`ID_PATH_SEPARATOR` |
| `IdGenerator.kt` | id 生成 | `IdGenerator.newId`、`UuidIdGenerator` |

**归一化是全局口径的锚点**：名称检索键、拼音输出、查询串、路径比较全部经过同一个 `normalize`；改归一化规则会同时影响检索与高亮换算（见 [`05-改动须知.md`](05-改动须知.md)）。
