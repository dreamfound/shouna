## 1. 易踩的口径陷阱

| # | 口径 | 真源在哪（改这里，别改别处） |
|---|---|---|
| 1 | 物品名拼音 = **持久化列**；位置路径拼音 = **构建时派生、不落库** | `ItemRepositoryImpl.createItemQuick` / `buildSearchDocs`；字段来源逐条写在 `SearchDoc` 类注释 |
| 2 | 四档权重与判档顺序 | `SearchConfig` 默认参数 + `SearchScorer.matchType`（**代码里的判定顺序即优先级**，勿从 PRD 抄） |
| 3 | 时间戳矩阵（谁写哪个时间） | `TimeUtil` 类注释 + `ItemRepositoryImpl` 的 `createItemQuick` / `confirmItem` / `setStatus`；**P1 新增的 4 行**（改字段 / 待归位 / 标临时 / 批量确认）落在 `updateFields` / `putBack` / `moveItem` / `confirmByLocation`。**2026-09-30 起「新建物品」也写 `last_confirmed_at`**（录入即确认，原为保持 NULL）—— 别再按旧矩阵给新物品留空 |
| 4 | 位置必填（`canSave` 口径 + 禁用文案） | `QuickAddViewModel.recomputeCanSave` + `QuickAddScreen` 的提示文案 |
| 5 | 「写失败不弹窗」取向 | `QuickAddViewModel.onSaveAndContinue`、`ItemDetailViewModel.mutate` |
| 6 | 内置哨兵不外露 | `BuiltInData.UNSPECIFIED_LOCATION` 是收容位；对外读取在 `LocationRepositoryImpl` 内 `filterNot { it.isBuiltIn }`，**不要在选择器 / 浏览页放开它** |
| 7 | 事务边界 | 跨表写必须走 `TransactionRunner`（位置删除）；单表写不走事务（`recordRecentQuery` 的裁剪是有意的无事务） |
| 8 | `GONE` 现在**真实产生** | `ItemRepositoryImpl.setStatus` / `restore`。F1 架构页「只产生 `in_storage`」是 F1 口径，已被 P0 覆盖 —— 不要照它写新代码 |
| 9 | F1 已交付的测试与模型不改 | `app/src/test/` 下 4 个 F1 单测文件保持不动；`SearchDoc` 新增字段一律带默认值，保证旧夹具仍可编译 |
| 10 | 浅色与字号是**三层锁** | Compose 侧 `ui/theme/Theme.kt`、窗口侧 `MainActivity.attachBaseContext`、资源侧无 `res/values-night/` —— 三层必须一致 |
| 11 | 系统栏与键盘避让是**容器级唯一职责** | `RouteHandler` 的 `NavHost` 上用 `systemBars ∪ displayCutout ∪ ime`；页面不各自处理。**含 IME**：键盘弹起时录入页「保存并继续」浮在键盘上方；**保存唯一入口 = 按钮**，IME 完成键只收键盘（`QuickAddScreen` 的 `onDone`） |
| 12 | 归一化是全局锚点 | `util/TextNormalizer` 同时被检索键、拼音输出、查询串、高亮换算使用 —— 改规则要连带核 `SearchScorer.highlightRange` 与全部单测 |
| 13 | **`location.path` 的默认值两处必须逐字一致** | `LocationEntity` 的 `@ColumnInfo(defaultValue = "''")` ↔ `Migrations.MIGRATION_1_2` 里的 `DEFAULT ''`。只改一处 → Room 迁移校验报「Migration didn't properly handle: location」 |
| 14 | **`path` 索引只认「区间」写法** | `LIKE :prefix \|\| '%'` 这种**表达式形态** SQLite 不走索引；子孙查询必须写成 `path >= :prefix AND path < :prefix \|\| char(0xFFFF)`。真源见 `LocationEntity` 索引声明处、`Migrations.kt`、`LocationRepositoryImpl.observeCounts` 三处注释 |
| 15 | **别名与名称同档参与检索**（`MatchType.NAME`） | `ItemRepositoryImpl.buildSearchDocs` 拆 `alias_blob`；上限 5 / 归一化去重 / 不与名称相同的判定在 `ItemEditViewModel.onAddAlias`；**改别名要同语句重算拼音列** |
| 16 | 统计数字的两个口径 | C-1 的「物品总数」= `status != 'gone'`（`ItemDao.observeActiveCount`）；「位置总数」= `is_built_in = 0`（`LocationDao.observeUsableCount`）。**别用 `observeTree().size`** —— 树会丢弃父级缺失的节点 |
| 17 | 「含子层」一律含子孙，「本层」不含 | `LocationRepositoryImpl.observeCounts`（两个数分开给）/ `ItemDao.confirmActiveInSubtree` / `SearchViewModel.subtreeIdsOf`。子树范围**按 ID 序列路径的父链算**，不要用会随改名而变的名称路径 |
| 18 | 内置分类**可改名不可删**，保护在**仓库层** | `CategoryRepositoryImpl.delete`（只删 `is_built_in = 0`）；`CategoryManageViewModel` 不重复判 `isBuiltIn` —— 别把这条守卫上移到 UI |
| 19 | 迁移**只增不改**，且**不得启用** `fallbackToDestructiveMigration` | `Migrations.kt` 的注释 + `di/DatabaseModule.provideShounaDatabase`。已升级的库不会再跑一遍旧迁移，改旧迁移体等于对存量用户无效；`fallbackToDestructiveMigration` 会让升级用户数据全丢 |
| 20 | 页面切换过渡**四个方向同一时长**，改时长必须**同时改 `enter` 与 `exit`** | `ui/navigation/RouteHandler.kt` 的 `NAV_TRANSITION_MILLIS`。库默认是 `fadeIn/fadeOut(tween(700))`；**只缩短 `exit` 无效** —— `AnimatedContent` 要等 enter 与 exit **两者都结束**，总时长仍取 700。`popEnter` / `popExit` 的默认值即引用 `enter` / `exit`，省略即自动跟随 |

> 第 10、11 条属**横切约束**：本表只给真源文件，规则本体与维护口径见 [`../实现约束.md`](../实现约束.md) §1。
