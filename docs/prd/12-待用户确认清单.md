## 11. 待用户确认清单（需用户拍板）

> 本清单**只列真正需要用户本人决定**的事项（不是产品经理能给默认值的）。其余问题均可按 [11-待确认问题清单.md](11-待确认问题清单.md) 的默认值推进，不必打扰用户。
> 每条的最后一列 = **若用户不回复，工程将按此默认值推进**，以保证不阻塞交付。

| 编号 | 问题 | 选项 | 我的推荐 | 若用户不回复，按此推进 |
|---|---|---|---|---|
| **U-1** | **数据要不要留「系统自动备份」这个兜底？**（架构约束 A-1，详见 [10-非功能需求.md](10-非功能需求.md) 的「系统自动备份与『仅存本机』的承诺冲突」） | **A.** 关闭系统自动备份：数据 100% 只在本机；换机/误卸载/设备损坏 = 数据全丢，唯一兜底是手动导出 JSON<br>**B.** 保留系统自动备份：数据可能由**系统**备份到**用户自己的云盘**（不经我方服务器）；此时「仅存本机」的文案必须改写 | **A** | **按 A 推进**：`allowBackup=false`（或显式排除数据库），同时把「导出备份」入口做得足够显眼 |
| **U-2** | **「待补详情」按什么口径算？**（架构约束 A-4，详见 [08-数据字段业务语义.md](08-数据字段业务语义.md) 的「待补详情判定口径」） | **窄口径（推荐）**：未填分类 **或** 主位置是内置「未指定位置」→ 待补<br>**宽口径**：再加上「无别名 / 无标签 / 无备注 / 数量为空」 | **窄口径** | **已按架构师建议的窄口径暂定**；若用户要宽口径，需重新评估统计页「天天提醒」的负担后再改 |
| **U-3** | **「超过多久没确认」算记录不可信？**（见 [11-待确认问题清单.md](11-待确认问题清单.md) 的 Q10） | 3 个月 / **6 个月** / 12 个月（设置页可改） | 6 个月 | 默认 **6 个月**，并允许用户在设置页改 3/6/12 |
| **U-4** | **首次启动是否给一套现成的位置树？**（见 [11-待确认问题清单.md](11-待确认问题清单.md) 的 Q9） | 提供模板「家 = 客厅 / 卧室 / 厨房 / 储物间 / 阳台」/ 从空开始 | 提供模板但**可跳过** | **提供模板且可跳过**，不强制使用 |
| **U-5** | **导出格式本期做到哪一步？**（见 [11-待确认问题清单.md](11-待确认问题清单.md) 的 Q5） | **仅 JSON**（本期）/ JSON + CSV（本期） | 仅 JSON，CSV 顺延下一期 | 按 **仅 JSON** 推进 |
| **U-6** | **标记为「已丢弃 / 已送人 / 已用掉」的物品，平时还看不看得见？**（FR-25，可信度表达见 [06-必须正面处理的难点.md](06-必须正面处理的难点.md)） | **默认从常规搜索与列表隐藏**，只在统计页可查/可恢复 / 始终可见但显示灰色失效标记 | 默认隐藏 | **默认隐藏**，统计页可查可恢复 |

**关于 U-1 的补充**：这是本清单中**唯一无法事后反悔成本较低**的一条（其余都是可配置项，用户随时能在设置页改）。U-1 一旦定成 B 再改回 A，需要考虑已经发生的云端备份；因此**这一条最需要用户明确表态**。
