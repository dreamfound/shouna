## 8. 归纳汇总（能力③的具体产出）

### 8.1 「归纳」到底要回答什么问题

| 用户问题 | 对应产出 |
|---|---|
| 我家一共有多少东西？ | **C-1 总览**（物品总数 / 位置总数） |
| 哪些记录可能已经不准了？ | **C-4 超期未确认物品** |
| 有哪些东西还没归位？ | **C-5 待归位清单** |

> **v1.3 变化**：由原 6 条精简为 **3 条**——只保留本期 3 张卡片（C-1 / C-4 / C-5）能回答的问题。原「分几类？」（C-2）、「哪些位置塞得最满？」（C-3）、「有哪些东西还不该算『有』？」（C-6）、「哪些记录信息不全？」（C-7）随对应卡片一并顺延下一期。
> **归纳能力的分层定位**：整个 P-STATS 页面属 **F2（深层）**，入口收在首页「更多」里，简化档不主动打扰用户。

### 8.2 统计卡片定义

#### 8.2.1 本期卡片（3 张，均属 F2）

| 卡片 | 名称 | 数据来源 | 计算口径 | 展示形式 | 点击行为 |
|---|---|---|---|---|---|
| C-1 | **总览** | 物品、位置、存放关系 | 物品总数 = 状态为「在存放中/待归位」的物品数；位置总数 = 全部非内置位置数；**存放关系数 = 全部 Placement 条数（⚠️ 口径取决于架构裁定：「一物一处」还是「多对多」，待架构师确认）**；**待补详情数 = 判定口径见 [08-数据字段业务语义.md](08-数据字段业务语义.md) §7.1.1（v1.3 已收窄为「只看主位置，且排除 `已不在`」）** | 4 个数字块 | 点击任一块 → 对应明细列表 |
| C-4 | **超期未确认物品** | 物品.最后确认时间 | 最后确认时间为空 或 距今 > 阈值（默认 6 个月，可配 3/6/12）的物品 | 清单 + 条数徽标 | 点击 → 明细列表，支持逐条「确认还在」与「按位置批量确认」 |
| C-5 | **待归位清单** | 物品.状态 = 待归位 **或** 物品位于「临时位置」 | 两部分去重合计。**v1.3 口径调整**：原引用的 FR-06「临时位置标记」已下沉 F2，简化档下临时位置只剩系统内置的「待归位区」，故**本条主口径为 `物品.状态 = 待归位`**；「位于临时位置」的部分仅在用户在 F2 自行标记过临时位置时才参与合计 | 清单 + 条数徽标 | 点击 → 明细列表，支持逐条「归位到…」 |

#### 8.2.2 顺延下一期的卡片（本期不做，不占任何 UI）

| 卡片 | 名称 | 顺延理由 |
|---|---|---|
| C-2 | 分类分布 | 「分类分布图」对只想简单记录的用户是纯负担；且简化档已把「分类」降为可跳过的 chips，分布图的数据基础本身也偏弱 |
| C-3 | 位置件数 Top N（含递归） | 面向搬家 / 大扫除场景（S-4），可顺延；递归口径本身也需要额外向用户解释 |
| C-6 | 已失效物品 | ⚠️ **状态收敛为 3 态（`在存放中 / 待归位 / 已不在`）后，本卡片「按 `已丢弃 / 已送人 / 已用掉` 分组计数」的计算口径本身已作废**——这三个状态已不存在。恢复场景改由 F1 的「还在」按钮直接覆盖，无需专门卡片 |
| C-7 | 待补详情 | 依赖 [08-数据字段业务语义.md](08-数据字段业务语义.md) §7.1.1 的判定口径（已定稿）；且在简化档下该卡片会变成「指责式提醒」，与压低录入成本的初衷冲突 |

> **顺延卡片的一并说明**：C-2 / C-3 / C-6 / C-7 的**口径定义保留在本文件**，便于下一期直接启用；本期任何页面都不展示它们。原「本期落地顺序建议」随卡片收敛作废，本期即 C-1 / C-4 / C-5 一并交付。

### 8.3 F2 卡片的出现条件（渐进披露）

> v1.3 采用**渐进披露**：**不做用户可见的「档位切换」**。F1 永远可见；F2 入口随数据量**自然出现**，避免用户一上手就看到一排自己还不需要的东西。

| F2 入口 | 出现条件（默认值，可配） | 说明 |
|---|---|---|
| **位置浏览（P-BROWSE）** | 位置总数 ≥ **3** 个 | 只有一两个位置时，搜索足够用 |
| **归纳统计（P-STATS）** | 物品总数 ≥ **10** 件 | 件数太少时统计无信息量 |
| 「显示完整功能」开关（P-SETTINGS 页内） | 始终可见，**默认关闭** | 逃生舱：用户手动打开后，**全部 F2 入口无条件显示** |

**规则**
1. 阈值存在应用配置中，**可配**；具体取值与存储方式**待架构师确认**（本 PRD 只给默认值）。
2. 未达阈值时，相关入口**不出现**（**不是灰置**）——避免让用户看到「还有个你现在不能用的功能」。
3. 用户打开「显示完整功能」开关后，**忽略一切阈值**，全部 F2 入口恒定显示。
4. 首页的一行摘要（「共 N 件物品 · M 个位置」）**不受阈值限制**，始终显示——它是 F1 元素③，不属于 F2。
