## 10. 待确认问题清单（按「影响架构决策的程度」降序）

> 每条均给出**建议默认取值**。若无异议，架构师可直接按默认值推进。
> **说明**：Q1–Q12 已被架构师采纳并落定为设计结论（架构侧引用**暂时移除**，另行处理），本清单在此仅作**需求侧口径留痕**。其中真正**必须用户本人拍板**的条目已抽出，见 [12-待用户确认清单.md](12-待用户确认清单.md)；其余均可按本表默认值推进。

| # | 待确认问题 | 为什么影响架构 | **建议默认值** | 状态 |
|---|---|---|---|---|
| Q1 | **本地存储方案选型**（关系型数据库 / 键值 / 文件） | 直接决定数据层设计与查询能力；搜索性能、拼音检索、多对多关系都依赖它 | **默认：本地关系型数据库（SQLite 类）+ 内存索引/归一化检索字段**；不引入网络依赖 | ✅ 架构已采纳（Room） |
| Q2 | **「一件物品多处存放」是否本期就做** | 决定数据模型是一对多还是多对多，后期改动成本极高 | **默认：本期数据结构即按多对多建模（Placement），UI 只默认暴露「唯一主位置」**，多处分摊作为进阶能力 | ✅ 架构已采纳（独立 placement 表） |
| Q3 | **数量字段是否本期做、是否要单位** | 影响物品字段与统计口径 | **默认：仅支持整数数量、默认 1、不做单位换算**；同一位置多处存放时用「该处数量」表达 | ✅ 架构已采纳；语义见 [08-数据字段业务语义.md](08-数据字段业务语义.md) |
| Q4 | **位置层级是否限制深度与「类型」** | 影响位置模型与 UI 导航 | **默认：层级深度不硬限制**（UI 软提示建议 ≤5 层）；「房间/柜子/箱子/格」仅作**可选类型标签**，不做强约束。（**v1.3 分层关联**：位置树的**浏览与管理**属 F2，F1 只暴露一个「位置选择器」字段，可留空） | ✅ 架构已采纳 |
| Q5 | **数据导出的格式与范围** | 决定序列化方案与导入兼容性 | **默认（已对齐架构）：本期只做 JSON**（单一文件、完整、可回导，覆盖物品/位置/分类/标签/存放关系/别名）；**CSV 作为「便于人看」的辅助格式顺延到下一期**，本期不做。理由：JSON 一份即可同时满足「备份/恢复」与「可迁移」，多出一个 CSV 只会增加导出逻辑与格式漂移的维护面，而本期真正的风险是数据丢失，不是可读性 | 🔧 已修正（本期仅 JSON） |
| Q6 | **删除是否走回收站（软删除）** | 影响所有查询的过滤条件与数据生命周期 | **默认：本期不做回收站**，但对「失效物品」用状态表达（可恢复）；物理删除操作强二次确认。（**v1.3 分层关联**：F1 档下删非空位置由**系统自动**把其下物品回落「未指定位置」，用户无感；「一并删除 / 迁移到指定位置」二选一只在 **F2** 出现。另：状态收敛为 3 态后，「失效」仅表现为 `已不在`，原 C-6「已失效物品」卡片已**顺延下一期**） | ✅ 架构已采纳 |
| Q7 | **「确认还在」的粒度** | 影响交互与数据字段（单件确认 vs 位置确认） | **默认：物品级 `最后确认时间` + 位置级批量确认动作**（批量确认会写入其下每件物品的确认时间） | ✅ 架构已采纳 |
| Q8 | **拼音检索的实现方式** | 影响依赖引入与包体积、以及是否需要预生成索引 | **默认：离线内置拼音库，录入时预生成全拼 + 首字母检索键并持久化**；不支持谐音/声调纠错 | ✅ 架构已采纳（仅名称+别名派生键，见 [08-数据字段业务语义.md](08-数据字段业务语义.md)） |
| Q9 | **是否预置初始分类与位置树** | 影响首次体验与初始化逻辑 | **默认：预置 6–8 个内置分类（不可删可改名）+ 首次启动自动预置默认位置树（不询问、不弹选择界面）**。默认位置树内容：`家 / 卧室 / 客厅 / 厨房 / 储物间 / 阳台` 共 **6 个节点**（走普通写路径，**可改名可删**）；另加系统「**待归位区**」（`isTemporary`，**可删**）与系统「**未指定位置**」（**不可删**，承载「位置可后补」的兜底）。用户可在设置页「**重置为默认位置树**」或「**清空位置树从头建**」 | ✅ 架构已采纳（**v1.3 将「可选模板」改为「自动预置」**） |
| Q10 | **「超期未确认」的默认阈值与提醒方式** | 影响统计口径与是否需要通知能力 | **默认：阈值 6 个月（可配 3/6/12）；仅统计页展示，不做系统通知**（避免申请通知权限，保持零权限） | ⏳ 阈值项列入 [12-待用户确认清单.md](12-待用户确认清单.md) |
| Q11 | **是否需要「别名」字段本期就上** | 影响检索字段数量与录入门槛 | **默认：本期做，但完全可选**（不填不影响保存），因为「家人叫法不同」是搜索命中的关键 | ✅ 架构已采纳 |
| Q12 | **是否允许同名物品 / 是否需要数量合并提示** | 影响录入校验与重复购买场景（S-2） | **默认：允许同名**（靠位置区分），仅在保存时给**非阻塞**提醒「家里可能已有这件」 | ✅ 架构已采纳 |
