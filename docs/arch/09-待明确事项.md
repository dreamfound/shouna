## 8. 待明确事项

### 8.1 架构约束（对 PRD 的建议修正，不改 PRD 原文）

| # | 事项 | 我的建议 | 理由 |
|---|---|---|---|
| **A-1** | `android:allowBackup` 当前为 `true`，与 NFR-09「仅存本机、卸载即永久丢失」及 NFR-17「不采集任何用户数据」**冲突**（Android 自动备份会把 DB 上传到用户 Google Drive） | **改为 `allowBackup="false"`**，或在 `data_extraction_rules.xml` 中显式排除 shouna DB | 否则「仅本机离线」的承诺在系统层面不成立 |
| **A-2** | [PRD 08 数据字段业务语义](../prd/08-数据字段业务语义.md) §7.6 要求「位置名（含路径各级）参与检索」，但位置名会随重命名/移动变化 | **位置/分类名不进物品行做冗余持久化**，只在构建内存 `SearchDoc` 时 JOIN 拼入；`item` 上只持久化「名称+别名」派生的检索键 | 避免改名/移动触发全表物品行重写（写放大与不一致风险） |
| **A-3** | [PRD 08 数据字段业务语义](../prd/08-数据字段业务语义.md) §7.2「同一父级下建议不重名」为**软校验**，但根级位置在 SQLite 中 `UNIQUE(parentId,name)` 对 NULL 不判重 | 根级重名由**应用层**拦截提示；或额外加 `CHECK`/生成列方案（复杂，不建议） | 保持软校验语义，不引入复杂约束 |
| **A-4** | [PRD 08 数据字段业务语义](../prd/08-数据字段业务语义.md) §7.1 的「信息完整度/待补详情」为派生字段，但未给精确判定 | 建议精确判定：**`item.categoryId IS NULL` 或「主位置是内置『未指定位置』」 → 待补详情** | 需产品确认；这是 C-7/FR-13 的统计口径前提 |
| **A-5** | [PRD 06 必须正面处理的难点](../prd/06-必须正面处理的难点.md) §5.4 允许「一件物品多处存放」，但未定义多处时的**顶层数量语义** | 约定：`item.quantity` = 总数量；`placement.quantity` 为空则继承总数，非空则为此处分摊数；**不强制求和一致**（允许用户不精确） | 避免强制校验阻碍极简录入 |

### 8.2 其余未决问题及建议默认值

| # | 问题 | 建议默认值 |
|---|---|---|
| B-1 | 超期阈值存储位置 | `app_config.threshold_months`，默认 `6`，可 `3/6/12` |
| B-2 | 连续录入的会话计数是否跨页面保留 | 仅当前 P-ADD 页面会话内有效，离开即清零 |
| B-3 | 重名提醒（FR-14）匹配口径 | 归一化名称**完全相等或前缀相等**即提示（非阻塞） |
| B-4 | 位置模板（FR-07）默认内容 | 「家 = 客厅 / 卧室 / 厨房 / 储物间 / 阳台」，用户可一键生成后自由增删 |
| B-5 | 最近搜索保留条数 / 最近位置条数 | 各 **8** 条，超出按 `lastUsedAt` 淘汰 |
| B-6 | 导出文件默认命名 | `shouna-backup-yyyyMMdd-HHmmss.json` |
| B-7 | 导入 MERGE 的同 ID 冲突策略 | **以文件内容覆盖**（同 ID 视为同一实体），不新建 ID、不删本地多余数据 |
| B-8 | 单条删除的「撤销」窗口 | **5 秒**（Snackbar），仅内存补偿，非回收站 |
| B-9 | 内置分类数量与名称 | 电器 / 衣物 / 工具 / 文具 / 药品 / 食品 / 清洁 / 其他（8 个） |
